# 节点评分

一个组如何把[健康检查](/zh/configuration/shared/health-check/)的结果变成它挑选节点的依据，以及每一部分为什么是这个形状。

本页讲的是理由，不是字段：可配置项见[负载均衡](/zh/configuration/outbound/loadbalance/)和
[URL 测试](/zh/configuration/outbound/urltest/)。

### 评分目标：快与稳

评分前先明确要优化什么；一个组选择其中一个目标，而不是把两个目标混成一个分数：

- `quick`：**节点通常有多快？** 170ms 的节点通常比 40ms 的节点更慢。
- `idle`：**节点现在比自己最好时多等多少？** 一个平时 200ms、晚高峰常驻 600ms 的节点，会拖慢高峰时的每一段流量。

两者回答不同问题：`quick` 关注延时水平，`idle` 关注延时里**由排队造成的那部分**。除非有模型说明一次卡顿应当折合成多少毫秒的常态延时，否则没有客观依据把它们加权成一个目标。

### 统计量：从成功检查中计算

延时统计只使用**成功**的检查。失败检查会等到超时，其耗时不能代表节点成功时的延时；失败次数和总检查次数会单独保留，供资格判断和 `quick` 的失败折算使用。

记 `x₁ … xₙ` 为本次窗口内成功检查的延时，`n` 为成功次数，`dᵢ = |xᵢ − MED|` 为每次检查偏离中位数的距离：

```
MED     = median(x₁ … xₙ)      # 本次窗口的延时中位数
JIT     = 1.4826 × median(dᵢ)  # 典型偏差
DEV     = (1/n) × Σdᵢ          # 平均偏差
```

`MED`、`JIT`、`DEV` 都由当前窗口算出，窗口一过就换一批。另有一个跨轮次保留的参考值：

```
SLOT     = 30 分钟一格，共 48 格，覆盖 24 小时     # 实现中的常量
slot[k]  = 第 k 格内见过的最快一次延时
BASELINE = min(最近 24 小时内各格的值)
STANDING = MED − BASELINE           # 常驻排队：典型延时比它自己最好时多等多久
```

`slot` 按墙钟对齐：`k` 由“当前时刻属于当天的第几个 30 分钟”决定，所以每一格永远对应同一天中时段。进入一格时先把该格重置为本轮最快的那次延时，此后取格内最小值；24 小时后同一格被下一次记录覆盖，于是自然作废。详见[基线为什么排成一圈格子](#设计取舍基线为什么排成一圈格子)。

因此 `BASELINE` 记录的是这个节点**在各个时段最好能有多快**，而不是某一事件之后的最低值。它不需要单独的过期计时器：有效期就是环的长度。

顺序上是先写格、再算分，让数据立刻生效。这样写不会把分数变成零：一格取的是最小值，所以 `BASELINE ≤ MIN ≤ MED`，写进去之后 `STANDING` 仍然非负。第一轮也没有单独的降级分支——那时格子里只有本轮的最快一次，`STANDING` 恰好就是 `MED − MIN`，与成熟形态是同一个式子。

因此 `STANDING` 也不会为负。节点变快时基线跟着下移，分数自动变小；节点变慢时基线不动，分数变大。方向不需要另外处理。

以上公式描述至少有两次成功检查时的统计量。只有一次成功检查时，无法从数据估计波动；实现将 `JIT`、`DEV` 和 `STANDING` 都设为该次延时的一半，避免把“没有足够样本”误当成“完全没有波动”。没有成功检查时，则没有延时统计量。

`MIN` 是本次窗口里最快的那次检查，它既是基线每次取值的来源，也近似“管道排空”时的延时：传播延迟加最少的处理时间。

`MED` 表达延时水平。`JIT`、`DEV` 与 `STANDING` 都描述波动，因此不包含节点有多快的信息，但原因不同：`JIT` 与 `DEV` 量的是相对本次窗口中位数的偏差，中位数换了它们跟着换；`STANDING` 量的是当前比**它自己的历史最好水平**多等多少。稳定在 4s 和稳定在 100ms 的节点，这三种波动可以一样。

- **`MED`** 用中位数而不是平均值，减少单次慢检查对典型延时的影响。
- **`BASELINE`** 就是**见过的最快一次延时**，不做任何平滑。代价是一次走运的探测会把基线压低，此后这个节点一直背着几毫秒的假排队；换来的是这个量不迟钝。按中位数记录时，平稳时段里每个节点都等于自己的中位数，`STANDING` 于是全为零，`idle` 就没有排序可言——一个在两个带宽池之间规律轮转的节点（两次 570、两次 1265，中位数正好落在两峰中间的 919）也会被当成最稳的一个。
- **`STANDING`** 是排队造成的常驻延时代价。链路被挤满时，缓冲区里排队的报文把延时推高，这个差值就是那段排队时间。因为减的是同一个节点的历史最好水平，传播延迟被抵消，所以不随节点远近漂移。
- **`JIT`** 用偏差的中位数表示**典型波动**。少数尖峰通常不会明显推动它；`1.4826` 是正态分布下把偏差中位数换算到标准差刻度的常数，见[推导](#推导)。
- **`DEV`** 用偏差的平均值表示**总体波动代价**。每次检查都计入，偶发尖峰会增加一份影响，重复尖峰会累积。它仍然计算并出现在报告里，用于排查，排序不再使用它。

因此，几个波动指标的区别是如何汇总同一批检查：

| | 问题 | 结论 |
| --- | --- | --- |
| `JIT` | 它通常波动多少？ | 卡过一次的节点仍然是近的节点 |
| `DEV` | 它总共多付了多少？ | 会卡的节点不是稳的节点 |
| `STANDING` | 现在比它自己最好时多等多久？ | 拥堵会一直留在计时里，直到它真的散去 |

### 分数：延时与排队

两个目标的公式不同，因为失败在两个目标里的位置不同。

`quick` 的分数是节点通常的代价，成功与失败按各自的份额加权。记 `ALL` 为总检查数，`FAIL` 为失败数，`TIMEOUT` 为健康检查超时：

```
base    = MED + JIT
cost    = min(TIMEOUT, base)
failure = min(TIMEOUT, 3 × cost)
score   = (ALL - FAIL) / ALL × cost + FAIL / ALL × failure
```

通常延时较低、典型波动较小的节点得分更低：波动按毫秒加入延时成本。

`cost` 是成功检查下的分数基础项，`failure` 是失败检查对应的惩罚项。一次失败按最多三倍成功成本计入，并以 `TIMEOUT` 封顶；这是评分策略，不是对实际请求重试耗时的精确测量。直接把每次失败都按完整超时计分，会使一次失败就可能压过所有未失败节点。

`idle` 的分数只是常驻排队，失败不进入分数：

```
score = min(TIMEOUT, STANDING)
```

只比较常驻排队，不比较延时水平：平时 400ms 和平时 100ms 的节点都可能一点都不排队，而一个平时 100ms、偶尔排队到 600ms 的节点就不行。分数相同的节点按 `spread` 小者优先。

失败为什么不能折算进来？`STANDING` 可以接近零，三倍 `STANDING` 也接近零。在一个真实窗口里，一个十次检查失败五次、成功时延时停在 410ms 的节点，常驻排队只有十几毫秒，按三倍折算后仍然只有几十毫秒；同一个窗口里十次全成功、排队到 200ms 的节点反而排在它后面。**排队的毫秒数与失败的代价不在同一个量级上，没有系数能把它们兑换**：在一个真实窗口里常驻排队的跨度可达 170 倍，而一次失败的代价在绝对时间上大致恒定，两者的比值因此从几十倍变到零点几倍。因此 `idle` 把失败当作资格问题：`max_fail` 规定窗口内允许的失败次数，超出者不再是合格节点。这需要为 `idle` 组配置 `max_fail`，否则失败的节点仍可能排在前面。

如果所有检查都失败，成功延时未知，两个目标的分数都记为 `TIMEOUT`；如果尚无检查结果，则没有可用分数。

分数是有限次检查得到的观测值，不等于节点或线路的恒定“真实值”；比较节点时要考虑它的估计噪声。

### 噪声：分数的不确定性

分数由有限次检查计算，因此是估计值，不是节点恒定不变的属性。换一批检查，分数可能改变；两个节点的分数差也会随之改变。这里的 `n` 是成功检查数，与计算失败比例所用的 `ALL` 不同。

#### 单个节点的噪声估计

标准误差描述“如果重测一批，估计分数通常会波动多少”。样本均值的标准误差可用样本标准差除以 `√n` 估计；中位数和以估计中心为基准的统计量还受分布形状影响。实现采用以下近似噪声估计：

```
SE_proxy(STANDING) ≈ 1.2533 · sd(x) / √n                            # idle
SE_proxy(score)    ≈ √( (1.2533·sd(x)/√n)² + (1.858·sd(d)/√n)² )     # quick
```

这里用 `SE_proxy` 表示实现采用的噪声估计，不表示有限样本下精确的标准误差。它只用于[迟滞](#保留已有连接迟滞)，即判断一个在用节点是否已经明显落后；[容差带](#选择节点容差带)用的是同一形状、但换成 `JIT` 估 `σ` 的尺度，因为它回答的是另一个问题，见 [`idle` 的余量为什么用 `MED` 的误差](#idle-的余量为什么用-med-的误差)。

两个目标的第一项是同一个量：分数里都含 `MED`，中位数就是 `MED` 的误差。`STANDING` 的噪声只来自 `MED`，因为基线是跨窗口保留的定值，不随本次窗口变动——这是它比“窗口内的离散度”更稳的原因：后者要看两个极值，前者只看一个已经定下来的数。

启动后的第一轮，基线就是本轮的最快一次，于是 `STANDING = MED − MIN`，`MIN` 是一个极值、噪声比 `MED` 大；那一轮的余量会低估实际波动，切换略偏积极。从第二轮起基线由多轮汇总，这个偏差就小到可以忽略。

这些估计依赖检查结果近似独立、分布在窗口内大致稳定等条件；小样本或明显趋势下尤其可能失准，详细说明见[推导](#推导)。成功样本少于 2 个时，实现使用基础分数作为噪声估计，而不套用上述公式。

#### 两个节点分数差的噪声

若两个节点的测量误差独立，它们的方差可以相加：

```
SD(score_node − score_best) ≈ √(SE_proxy_node² + SE_proxy_best²)
```

若两者受到共同探测目标或共享线路状况影响，误差可能相关，差值方差还应包含 `−2·Cov(score_node, score_best)`。当前公式把协方差视为零，是一个简化假设。独立时先平方相加再开方，得到差值的标准差；这不是把两个误差直接相加，也不表示噪声会被消除。推导见[推导](#推导)。

#### 为什么不能从分数里“减掉噪声”

噪声不是固定偏差，而是围绕估计值的波动，不能从分数中扣除一个通用数值。它能缩小的方式取决于统计量：分数里含 `MED` 的那部分随 `1/√n` 缩小，不随窗口变化的基线则是定值。选择策略通过**容差带**容忍这种不确定性，而不是试图从每个分数里减去噪声。

### 选择节点：容差带

选择时，组会把分数接近最佳节点的候选视为“同样好”，不因很小或不确定的差别频繁切换。`tolerance` 是可配置的分数差范围；默认值不同，是因为两个目标的分数衡量不同的量：

| 目标     | 分数        | 默认   |
| -------- | ----------- | ------ |
| `quick`  | `MED + JIT` | `50ms` |
| `idle` | `STANDING`  | `10ms` |

实际选择带还会加上**分辨力余量**，用于避免把测量波动误当成节点差异。两个目标的分数都是绝对毫秒，余量形状相同：

```
band = tolerance + 2√2 × 噪声_best / √n
cut  = score_best + band
```

`quick` 的噪声取 `JIT_best`；`idle` 的噪声取 `1.2533 × JIT_best`，多出的系数是因为它的分数是一个中位数。两者都取**典型偏差**（`JIT`），不取离散度 `sd(x)`：余量的职责是把节点分开，一个被单次慢探测撑大的余量会把所有节点都吞进去，见下一节。系数 2 是工程上的启发式取值，不是 95% 置信保证。

实现只在成功样本数 `n ≥ 2` 时加入噪声余量；`n < 2` 时 `band = tolerance`。

候选分数不高于 `cut` 时，仍在可选范围内。样本增多会缩小余量中的 `1/√n` 项，所以 `band` 会趋近配置值，但**不会窄于 `tolerance`**。

#### `quick` 的余量为什么取 `JIT_best`

比较前不知道候选节点是谁、测量有多准，所以实现假设候选与最佳节点测得一样准；两边都用最佳节点的 `JIT` 作为噪声尺度。

```
margin = 2 × √( (JIT_best/√n)² + (JIT_best/√n)² )
       = 2√2 × JIT_best/√n
```

噪声尺度取 `JIT_best`：

- **不取 `DEV_best`**：`DEV` 是平均偏差，一次尖峰只按自己的份额计入，用它估余量会把“偶尔卡一次”的节点算得比实际更稳；而 `JIT` 取偏差的中位数，对少数异常值不敏感，更适合当噪声尺度。
- **不直接用完整的分数噪声估计**：它含有平方离差，一次慢探测可能把估计撑大；余量随之变宽，会让明显更差的候选也进入范围。这是一项稳健的工程取舍，不是实际噪声的数学下界或 95% 分辨力保证。实测窗口中，分数噪声估计与 `JIT_best/√n` 的比值曾约为 2.8；该比值依赖数据分布和窗口，不能视为通用常数。

#### `idle` 的余量为什么用 `MED` 的误差

`STANDING` 等于 `MED` 减去基线，而基线是跨窗口保留下来的定值，本次窗口的抽样不会改动它。所以分数的噪声就是 `MED` 的噪声，也就是中位数的标准误差：

```
SE(MED) ≈ 1.2533 · σ / √n
```

要估的是 `σ`，即节点单次检查的波动。余量取 `JIT`，即偏差中位数换算出的稳健刻度，而不取 `sd(x)`：

```
margin = 2√2 × 1.2533 × JIT_best / √n
```

因为 `sd(x)` 会被一次慢探测撑大，而**余量的职责是分辨**。`idle` 的分数本身对尖峰不敏感（见[设计取舍](#设计取舍standing-对单次尖峰不敏感)），余量若对尖峰敏感，两者就分家了：分数说这个节点正常，余量却告诉组里谁都说不准，`idle` 于是失去排序。这与 `quick` 的余量取 `JIT_best`、不取完整的分数噪声估计，是同一条取舍。

代价是 `sd(x)` 更能反映“换一批检查，中位数会跳多少”——尖峰多的节点，中位数确实会跳。宁可让排名跟着中位数一起动，也不要让余量大到排名不存在。

这个余量是**绝对**的：它不随分数大小变化。因此 `idle` 的分辨力不因节点排不排队而变——一个常驻排队 500ms 的节点和一个几乎不排队的节点，用的余量相同。这也让 `tolerance` 的默认值 `10ms` 有意义：分数以毫秒计，余量也在几十毫秒量级，配置值和实际带宽处在同一尺度上。

样本越多，这个余量越小，这与 `quick` 一致。基线本身的不确定性小于 `MED` 的，因为它由多个窗口汇总而来。

### 保留已有连接：迟滞

开启打断链接配置后，节点被替换时，原有连接可以暂时保留。刚离开选择范围的节点，只要它超过选择带的部分仍在噪声余量内，就不会立即断开连接：

```
noise     = 2 × √(SE_proxy_node² + SE_proxy_best²)
allowance = band + min(band, noise)
```

这里比较的是具体的在用节点和最佳节点，因此分别使用它们自己的噪声估计。两个估计按独立误差合成；共享目标或线路导致的相关性仍被忽略。`min(band, noise)` 把额外保留范围封顶为一个 `band`，所以节点最多保留到距最佳节点**两倍带宽**处。迟滞用于应对测量波动，不用于长期保留明显更差的节点。

`idle` 的 `SE_proxy` 用完整的离散度 `sd(x)`，带宽却按 `1.2533 × JIT` 算，两者可以差一个数量级，于是 `min(band, noise)` 落在 `band` 上，保留范围就是**两倍带宽**。这正是封顶的用途——两个数回答的是不同问题：带宽要多窄才能分辨节点，噪声估计是某个已知节点的分数可能差多少。

#### 为什么连接保留也使用噪声估计

连接保留和选择带都在处理“观测差异是否足够可信”，但回答的问题不同：选择带要对所有未知候选采用统一、稳健的余量；连接保留面对的是一个已知节点，因此可以使用该节点和最佳节点各自的噪声估计。这里的系数 2 同样是工程启发式，不代表严格的置信概率。

#### `quick` 与 `idle` 的表现

- `quick` 的噪声估计由延时样本的离散度和绝对偏差的离散度共同决定，样本越多越准。
- `idle` 的噪声估计只来自 `MED`，比 `quick` 少一项，也更早随样本增多而缩小。它的分数不因窗口换了就归零：一个节点开始拥堵后，只要基线还是它空闲时的那个值，`STANDING` 就会一直把它送出选择带，直到拥堵缓解、或者基线因有效期到期而重新学起。

#### `urltest` 的单节点选择

`urltest` 一次只选择一个节点，没有负载均衡组的第二层连接保留。迟滞直接放在选择中：在用节点的分数不超过最佳节点的 `Limit(best)` 时继续使用，即最多容忍**一个带宽**的差距。

连接保留与节点选择是两项独立决策：前者决定要不要中断已有连接，后者决定新连接可以使用哪些节点。

### 设计取舍：为什么不按标准差排序

样本标准差是常见的离散度指标，但不适合作为这里的节点波动分数，原因有三点：

1. **它以平均值为中心，而平均值会被离群值拉走。** 十次检查里一次慢速，均值从 449ms 抬到 897ms，
   剩下九次的偏差就被拿去和一个与它们无关的中心比较：它们 457ms 的偏差变成了 751ms，而它们一个都没变。
2. **它有平方，于是一个样本可以主导结果。** 在某个窗口里一次检查用了 3.15s，83% 的方差来自那一次，
   报告出来的离散度描述的是那一次探测，而不是节点。
3. **开方并不能把尺度还原。** `n` 个样本中一个 `X` 的尖峰，对平均偏差的贡献是 `X/n`，
   这正是它拖慢的连接份额；但对标准差的贡献是 `X/√n`——`n = 10` 时就已经高估 3.2 倍，窗口越长越离谱。

`DEV` 仍然计算相对中位数的偏差，但采用线性平均，不让一个尖峰移动中心。在 200ms 与 800ms 之间来回的节点仍会有较大的 `DEV`；它不是忽略不稳定，而是避免让一个样本单独决定分数。

`idle` 现在按 `STANDING` 排序，也是线性的：常驻排队就是一个延时差，不是平方。区别在于它量的不是“窗口内忽快忽慢多少”，而是“比它自己最好时多等多少”。这两件事在窗口里可能出现同样的离散度，但后果不同：一个在 200ms 和 800ms 之间来回的节点，中位数被拉到 500 附近，而它的基线仍是 200，`STANDING` 约 300；一个稳定在 800ms 的节点，基线也是 800，`STANDING` 为零——它从未更快过，所以当前这个慢不是排队造成的。**`idle` 选后者。** 稳定的慢是一个可以用 `max_rtt` 处理的已知成本，忽快忽慢不是：同一段流量时快时慢，没法预先支取。

这不表示标准差完全不用：`quick` 仍用样本标准差估计分数噪声；这里的取舍是**不把它直接当作节点排序分数**。

### 设计取舍：为什么趋势不直接进入分数

窗口是有顺序的，而上面所有统计量都没有用到它：把样本打乱，`MED`、`STANDING`、`JIT`、`DEV` 都不变。
因此一个已经持续变差十分钟的节点，只要延时水平一致，读数和一个一直这样的节点一样。

`STANDING` 部分补偿了这一点，但方式和趋势不同：它比较的不是窗口内的先后顺序，而是**当前与历史最好**。一个从 200ms 变到 600ms 的节点，`MED` 立刻变成 600，基线还是 200，`STANDING` 立刻变成 400，不需要等趋势累积；一个从 600ms 变到 200ms 的节点，基线跟着降到 200，`STANDING` 立刻回到接近零，也不会被过去的坏状态连累。**方向因此不需要额外处理：基线只向下移动，改进会立刻被认可，恶化会立刻兑现。**

半窗对比（`median(后半) − median(前半)`）确实能再提供一层信息，而且代价很低：它能分辨“刚开始变坏”和“已经坏了一会儿”。它没有进入分数，是因为含趋势的分数会让 `interval` 变化时排名也变化，而排名必须是节点自身的性质，不是它被采样的节奏的性质。趋势属于决策，与容差并列，不属于测量。

它也需要小心：`sampling` 为 10 时，后半窗五个样本里连续两次异常并不能推动它的中位数，因此趋势要到第三次才会出现。
这使它成为一个比“最近一次检查”更慢的信号，而后者本来就在统计量里。

窗口长度也有类似的取舍：在延时分布相对稳定时，窗口越长，估计通常越平滑、噪声越小；但旧样本占比也越大，节点发生变化后分数跟上的速度越慢。缩短窗口会更快反映变化，但估计也更容易受偶然波动影响。因此，降低噪声和跟上变化是同一个采样窗口选择的两端。

### 设计取舍：基线为什么排成一圈格子

基线记录“这个节点最好的状态”，于是同时受两个相反的约束：**它必须记得足够久**，因为空载只在日低谷出现，看得太短就会把拥堵时的水平当成空载水平；**它又必须忘掉**，因为同名节点可能换了线路、换了机器，旧基线立刻是错的。

一个“何时过期”的计时器很难同时满足两头，因为过期是一次性事件：到点之前什么都不变，到点之后一次全丢。改成**一圈格子**，两个约束就都变成连续的：

```
48 格 × 30 分钟 = 24 小时
每 30 分钟只有一格被重置，其余 47 格照旧
```

- **记得够久**：环覆盖满 24 小时，每个时段都有自己的记录，所以任何时刻都至少有一整天的证据在支撑基线。
- **忘得平滑**：没有“过期”这个动作，只有一格被下一次同格记录覆盖。基线不会在某一个瞬间整体作废，也不会因为一次重置让全组的分数同时归零。

格的划分按墙钟而不是按运行时长，所以第 40 格永远是 20:00–20:30。这一点让“记住”变得更准：每一格记的是**这个时段最好能有多快**，而不是任意的 24 小时窗口内的最低值。

格子数量是记忆粗细与单格可靠性之间的旋钮：格越少，单格跨度越长，一个时段内的变化会被压成那一个最小值；格越多，单格里的探测越少，记录只由一两次探测决定。48 格刚好整除一天，并且让每格容纳若干轮检查。它与 `sampling`、`interval` 一样是**实现里的常量，不是配置项**：改它要同时考虑探测频率，不适合交给配置。

**代价。** 基线是每格最小值的再取最小，仍然是“最小值”，所以它偏向记录最乐观的一次。这与它的用途一致（要的是空载水平），但意味着偶尔一次走运的探测会略微压低基线，见[推导](#推导)里对估计方式的比较。

#### 更新、过期与启动

**更新。** 每轮先写格、再算分，所以本轮的观测立刻生效：

```
slot[k]  = min(slot[k], MIN)               # 进新格时先重置为 MIN，再取格内最小值
BASELINE = min(最近 24 小时内各格的值)
STANDING = MED − BASELINE
```

先写不会让分数归零：一格存的是最小值，因此写完之后 `BASELINE ≤ MIN ≤ MED`。若反过来先算分再写，节点变快时要等下一轮才被认可，没有任何好处。

成功样本少于两次的轮次不写：那一次可能是运气，也可能只是探测还没进入状态，不该用它给一天定一个下限。这一轮的 `STANDING` 取该次延时的一半，见[统计量](#统计量从成功检查中计算)。

**过期。** 没有单独的过期动作：一格在 24 小时后被同格的下一轮记录覆盖，自动退出。因此基线永远来自**真实观测过的时段**，不会像“到点重置为当前值”那样，把当下的拥堵水平误记成最好水平。若某个时段此后一直拥堵，它的记录会随时间抬高，但其它时段的记录仍然有效——除非常年如此，那时基线才整体抬起来，等于承认“这个节点就是这样”。

**跳变。** 平稳与缓慢变化时，基线每次最多移动一格的变化量，因为每 30 分钟只有一格被换掉。用一个每天劣化 144ms 的节点模拟：一次性过期的做法会出现一次 144ms 的台阶，格子式则每次约 11ms，分散在一天 48 次里。**但阶跃式变化（换线路、换机器）仍会留下一次台阶**：最小值这个聚合器在最后一格旧数据被覆盖的那一刻，必须跳到下一个最小值，幅度就等于变化本身。这是“忘记”这件事本身，不是可以抹平的抖动。

**启动。** 第一轮写进格子的就是本轮的最快一次，所以 `STANDING` 一上来就是 `MED − MIN`，没有单独的降级分支。此后基线由一格起步逐格长满，一天后覆盖完整。重启走同一条路：基线是内存里的记录，重启后重新长一遍；恢复期内每格只覆盖了较少的时段，基线因此更容易被压低——这是“忘记”的代价，不会让分数失去意义。

### 设计取舍：`STANDING` 对单次尖峰不敏感

`STANDING` 减的是中位数，而中位数只由排序位置决定：十次检查里出现一次三秒的尖峰，中位数仍然是剩下的那个典型值，`STANDING` 几乎不动。持续拥堵会推动中位数，一次卡顿不会。

这与“偶尔卡三秒会拖慢流量”的直觉有出入，取舍如下：

- **尖峰本身很短**。它影响落在那一刻的少数连接，而排队造成的抬高影响窗口内**每一次**连接。用分数去追尖峰，代价是让一次运气决定整个排名。
- **验证尖峰需要更多样本**。单次极值是全窗口最不稳的量，`idle` 若按它排序，分数会随窗口抖动，余量就得跟着放大，分辨力反而下降。
- **需要更敏感时，可以换更高分位**。把当前水平从 `MED` 换成 p90：在一次真实窗口里，一个中位数为 175ms、含一次 655ms 尖峰的节点，`MED − MIN` 是 20ms，而 `p90 − MIN` 是 117ms。分位越高越敏感，也越接近极值、越不稳。当前实现取中位数，因为它要回答的是“这段连接通常要等多久”。

### 推导

本节解释噪声估计中用到的公式、常数和假设。先约定记号：

- `n` 是成功检查的数量；`xᵢ` 是第 `i` 次成功检查的延时；`MED` 是这些延时的样本中位数。
- `sd(…)` 是样本标准差，用来估计一批数据通常离开其中心多远。
- `Var(…)` 是方差，即波动大小的平方；`SE`（标准误差）表示一个估计值在重复采样时通常会波动多少，等于方差开平方。
- `SE_proxy` 表示实现使用的噪声估计。它是近似值，不是精确标准误差或置信区间。

下面的推导会假设检查结果彼此独立，并来自一个采样窗口内稳定的分布。分析 `JIT` 时还会用到分布对称的假设；真实网络不一定完全满足这些条件。

#### `idle`：`STANDING` 的噪声估计

`idle` 按 `STANDING = MED − BASELINE` 排序。我们要估计的是：重新做一批检查时，这个差值通常会变多少。

**第一步：基线在一轮之内是常数。** `BASELINE` 由各格的最小值汇总而来，本轮写入之后它就是一个定值，减它是减常数，方差不变：

```
Var(STANDING) = Var(MED − BASELINE) = Var(MED)
```

本轮写入可以让基线**下移**（当这一轮出现了更快的一次），此时 `STANDING = MED − MIN`，还多带一点 `MIN` 的噪声。这是一个只在刷新记录时发生的、方向单一的事件，而不是每轮都有的抖动，所以噪声模型仍以 `MED` 为主。

基线本身的偏差是另一回事，它是**系统性的**：最小值偏低，每个节点都背着一段假排队，而这段偏差不会随抽样次数被平均掉，因此不进入标准误差，只能靠理解它的方向来对待，见第四步。

**第二步：`MED` 的方差。** 中位数只看样本的排序位置，因此它的方差取决于中位数附近的概率密度 `f(m)`：

```
Var(MED) ≈ 1 / (4n·f(m)²)
```

正态近似下 `f(m) = 1/(σ√(2π))`，代入得 `(π/2)·σ²/n`，开方即：

```
SE(MED) ≈ 1.2533 · σ / √n
```

`σ` 是节点单次检查的波动。实现用两个方式估它：`sd(x)` 是样本标准差，是标准误差的原始定义所用的量；`JIT` 是偏差中位数乘 `1.4826`，是同一刻度的稳健估计，单次尖峰推不动它。两者分别用在两处：迟滞取前者，余量取后者，理由见 [`idle` 的余量为什么用 `MED` 的误差](#idle-的余量为什么用-med-的误差)。`1.2533 = √(π/2)` 的来历见 [`quick`：`MED` 的误差](#quickmed-的误差)，两个目标用的是同一个量。

**第三步：合起来。** 把第一步和第二步接上，得到迟滞用的估计：

```
SE_proxy(STANDING) ≈ SE(MED) ≈ 1.2533 · sd(x) / √n
```

余量里把 `sd(x)` 换成 `JIT`，形状不变。两者都是**绝对**误差，不随分数大小变化。一个常驻排队 500ms 的节点和一个几乎不排队的节点，误差尺度相同——因为它们之间的差别只是减去的那个常数不同。

**第四步：基线取的是最小值，因此偏乐观。** 基线要回答“这个节点最好能有多快”，实现直接取见过的最快一次延时，不做平滑。用一天 1440 次检查、真实空闲 200ms、`sd = 8` 的模拟：

| 估计方式 | 得到的基线 | 空闲时读到的排队 |
| --- | --- | --- |
| **最小的一次（实现）** | **175** | **25** |
| 各窗口中位数的最小值 | 191 | 9 |
| 全天 10 分位 | 190 | 10 |
| 全天中位数 | 200 | 0 |

最小值系统地偏低约 3 个标准差：一天里有 1440 次机会，总有一次走运。代价是每个节点都背上几毫秒到几十毫秒的假排队，好处是这个量**不迟钝**。

按窗口的中位数记录会安静得多（偏差只有 9ms），但它回答的是另一个问题：“这个节点**通常**有多快”。平稳时段里每个节点的中位数都等于它自己，`STANDING` 于是全为零，`idle` 没有排序可言。更糟的是一类真实的节点：它的延时在两个带宽池之间轮换，两低两高时中位数正好落在两峰中间，一个它从未达到过的值，而这个中点逐轮稳定，于是它被读成最稳的一个（`MED = 919`、`MIN = 556`，按中位数记基线得 0，按最小值记得 363）。取最小值就不会被这种结构骗过。

这个偏差是**共同**的，不改变排序：两个节点都偏乐观几毫秒，它们在 `STANDING` 上的差仍然是它们真实差距的差。它只影响绝对零点，也就是 `tolerance` 的相对严格程度。

#### `quick`：`MED` 的误差

`quick` 的分数是 `MED + JIT`。先看 `MED`：换一批检查结果，中位数也会变。它的误差取决于中位数附近有多“挤”：样本集中在中位数附近时，中位数通常不容易移动；附近样本稀疏时，少量样本变化就可能让它跳得更远。

用 `f(m)` 表示总体中位数 `m` 附近的概率密度。它可以理解为“延时落在中位数附近的密集程度”。样本较多时，中位数的方差近似为：

```
Var(MED) ≈ 1 / (4n·f(m)²)
```

对正态分布，`f(m) = 1/(σ√(2π))`。代入后可得：

```
Var(MED) ≈ (π/2)·σ²/n
SE(MED)  ≈ √(π/2)·σ/√n
          ≈ 1.2533·sd(x)/√n
```

这里用样本 `sd(x)` 估计总体标准差 `σ`。因此 `1.2533 = √(π/2)` 是**正态分布近似**下的系数：在该条件下，中位数的标准误差约比均值大 25%。延时分布明显偏斜或样本很少时，这个系数不一定合适。

#### `quick`：`JIT` 为什么乘 `1.4826`

`JIT` 用绝对偏差的中位数表示“典型波动”，再乘 `1.4826`，把它换到与标准差相同的刻度。这个常数从正态分布推来：

```
q = median(|X − m|)
P(|X − m| ≤ q) = 1/2
```

对称的正态分布中，“落在 `m` 左右 `q` 以内”占一半概率，所以从均值到 `m+q` 的概率是四分之一，即 `Φ(q/σ)=0.75`。因此：

```
q = Φ⁻¹(0.75)·σ ≈ 0.6745·σ
σ ≈ q / 0.6745 ≈ 1.4826·q
1.4826 = 1 / Φ⁻¹(0.75)
```

也就是说，对正态数据，偏差中位数约为 `0.6745σ`；乘上 `1.4826` 后，`JIT` 就能估计标准差的尺度。它是正态分布下的换算常数，不意味着实际延时一定服从正态分布。

#### `quick`：`JIT` 的误差估计

即使知道真实中心 `m`，`JIT` 也会因抽到哪一批样本而变化。设 `q` 是 `|X−m|` 的总体中位数，`g(q)` 是绝对偏差在 `q` 附近的概率密度。中心已知、分布对称且样本足够多时：

```
SE(median(|X − m|)) ≈ 1 / (2g(q)√n)
SE(JIT) ≈ 1.4826 / (2g(q)√n)
```

直观上，`q` 附近的绝对偏差越密集，中位数越不容易移动，误差就越小。若中心也要从同一批样本估计，或延时分布不对称，计算还需额外考虑这些影响。

当前实现使用 `1.858·sd(d)/√n` 作为这部分的工程噪声估计，其中 `1.858 = 1.4826 × 1.2533`。这个近似相当于把正态中位数的系数用于 `d`；但即使 `x` 服从正态分布，绝对偏差 `d` 也服从半正态分布，所以 `1.858` 不是严格推导出的标准误差系数。它应理解为实现采用的估计值，而不是精确的概率保证。

#### `quick`：合并 `MED` 与 `JIT` 的误差

若两个量的误差独立，它们之和的方差就是各自方差相加；一般情况下还要加上协方差项：

```
Var(MED + JIT) =
    Var(MED) + Var(JIT) + 2·Cov(MED, JIT)
```

`MED` 与 `JIT` 用同一批样本计算，原则上可能相关。对称 IID 分布下，它们渐近独立，因此实现近似忽略协方差；有限样本或其他分布下，这不一定成立。当前实现的合成噪声估计为：

```
SE_proxy(score) ≈ √( SE_proxy(MED)² + SE_proxy(JIT)² )
```

因此，`quick` 中的系数和方差合成依赖上述分布与样本假设；这个 `SE_proxy` 是工程估计，不是 95% 置信区间。

#### 两个节点比较时，差值有多不确定

这一部分问的是：如果重新进行健康检查，节点分数与最佳节点分数之差会浮动多少。先记两个分数为随机量：

```
S_node   = 节点分数的随机量
S_best   = 最优节点分数的随机量
D        = S_node − S_best
Var(D)   = Var(S_node) + Var(S_best)
           − 2·Cov(S_node, S_best)
```

两个节点的测量误差独立时，协方差为零。若它们共用探测目标或受到同一线路状况影响，协方差可能不为零；当前实现忽略这项。独立假设下，把前面两项的噪声估计代入并开平方：

```
Var(D) ≈ SE_proxy_node² + SE_proxy_best²
SD(D)  ≈ √(SE_proxy_node² + SE_proxy_best²)
```

`SD(D)` 表示分数差在重测时的波动；公式中的 `SE_proxy` 是实现采用的估计，不是精确值。

#### `SD` 与 `SE` 是什么关系

`SD`（标准差）描述一个随机量的波动；`SE`（标准误差）描述一个估计值在重复采样时的波动。分数是根据样本计算出的估计值，因此它的标准差也就是它的标准误差。此处用 `SE_proxy` 表示实现对这个误差的近似估计。

`score_node` 和 `score_best` 在当前窗口里是已经观测到的定值；把它们称为随机量，是在问“如果重测一遍，它们可能变动多少”。
