# 节点评分

### 评分目标：绝对的速度，与相对的质量

支持评分的目标有两个：

- `quick`：**它通常有多快？** 170ms 的节点就是比 40ms 的慢。这是绝对时间，按毫秒算。
- `idle`：**它比自己最好的时候差了多少？** 一个平时 200ms、晚高峰长期 600ms 的节点，600ms 也许不算慢，但它已经在用自己四倍的时间跑，高峰时每一段流量都被它拖住。

两个问题的单位不一样，这点很关键。`quick` 比的是实际延时，`idle` 比的是退化。要是拿实际延时去衡量退化，远一点的节点永远吃亏，比的就成了距离，不是状态。所以 `idle` 用的全是比例，跟远近无关。

### 统计量：从成功检查中计算

失败的检查不算延时，它说明不了节点正常时有多快。失败次数和总数单独记录，用来判断节点够不够格，以及给 `quick` 算失败惩罚。

设窗口里成功检查的延时是 `x₁ … xₙ`，`n` 是成功次数，`dᵢ = |xᵢ − MED|`：

```
MED     = median(x₁ … xₙ)         # 这个窗口的延时中位数
JIT     = 1.4826 × median(dᵢ)     # 通常波动多少
DEV     = (1/n) × Σdᵢ             # 平均偏离多少
```

这三个只看当前窗口，窗口一动就重算。另外还有几个跨轮次留着的值：

```
SLOT     = 一天切成 48 格，每格 30 分钟
SLOT[k]  = 第 k 格里见过的最快一次
FLOOR    = min(最近 24 小时里各格的值)         # 它最好能做到多快
FAILR    = 近期的失败率，越久权重越轻           # 与窗口无关，见下文
PRES     = max(0, MED − FLOOR) / FLOOR      # 通常比它自己最好时多等了百分之多少
BAD      = #{xᵢ > 2 × FLOOR} / ALL + max(FAIL / ALL, FAILR)  # 没达标的比例
```

这些公式的前提是至少两次成功检查。只有一次时，说不出波动有多大，`JIT` 和 `DEV` 都取那次延时的一半——宁可当作有波动，也别把“样本不够”读成“一点波动都没有”。这时 `FLOOR` 就是那一次本身，两个比例也就无从谈起，所以 `idle` 干脆按延时排序（取一半）。一次都没成功，就没有延时统计量。

- `SLOT` 按墙上的钟切：`k` 是当天第几个 30 分钟。检查会写测试时所在格，格子内只保留最小值。过了 24 小时，同一格会被下一次记录盖掉，旧值自然失效。
- **`MED`** 是延时水平。用中位数而不是平均值，一次特别慢的检查拉不动它。
- **`JIT`** 是**通常波动多少**。少数尖峰推不动它；`1.4826` 是正态分布下把“偏差中位数”换算成标准差的系数。
- **`DEV`** 是**整体波动多少**。每次检查都算一份，尖峰多了才累积起来。它出现在报告里帮忙看问题，不参与排序。
- **`FLOOR`** 是**见过的最快一次**，不做任何平滑。一次走运的探测会把它压低，让节点之后一直显得在排队；换来的是它对变化反应很快。
- **`PRES`** 是排队**有多深**：比它自己最好时多等了百分之多少。除以它自己的地板，传播距离就抵掉了，远近节点比得了。
- **`BAD`** 是排队**有多频繁**：超过自己地板两倍的检查占多少，再加上失败占多少。它只跟自己地板比，同样与远近无关；一次特别慢也只算一次。失败那项取窗口内实测与 `FAILR` 里大的那个。
- **`FAILR`** 是**长期失败率**。老记录越来越轻，所以它说的是“最近怎么样”；它不看窗口，窗口里碰巧没失败也不会立刻归零。

### 分数：延时与排队

两个目标的公式不一样，因为“失败”在两个目标里站的位置不同。

`quick` 算的是这节点通常让你多等多久：成功的按成功算，失败的按失败算，再按各自份额加权。记 `ALL` 为检查总数，`FAIL` 为失败数，`TIMEOUT` 为健康检查的超时：

```
base    = MED + JIT
cost    = min(TIMEOUT, base)
failure = min(TIMEOUT, 3 × cost)
p       = max(FAIL / ALL, FAILR)
score   = (1 − p) × cost + p × failure
```

延时低、波动小的节点分数就低。一次失败最多按三次成功的成本算，还封顶 `TIMEOUT`。这是个评分规则，不是真去测重试花了多久——要是每次失败都按完整超时算，一次失败就足以盖掉所有没失败的节点。

`idle` 算的是排队的深浅加频次，失败只算进频次：

```
score = 1000 × (PRES + 0.5 × BAD)
```

`0.5` 是频次的权重，`1000` 是把无量纲的比例换成毫秒的标尺，于是两个目标的分数同一个单位，可以共用一个 `tolerance`：

| 目标 | 分数 | `tolerance` 默认 | 意思是 |
| --- | --- | --- | --- |
| `quick` | `MED + JIT`（毫秒） | `50ms` | 差 50ms 不值当切 |
| `idle` | `1000 × (PRES + 0.5 × BAD)` | `50ms` | 差 5% 不值当切 |

同一个 `50ms`，两边都是“这点差别不值得换”。日志和报告里也都是毫秒，不用记两套单位。

**失败为什么只进频次。** 失败没有延时可比，进不了深度那一项。要是拿 `TIMEOUT` 当它的延时，三十次检查里错一次就能把 `PRES` 抬高 0.8（约 800ms），把真正的排队差别全盖住。**排队的延时和失败的代价，本来就不该直接换算。**

换算是有的，只是很轻：`BAD` 每多 10%，分数多 50ms，也就是**10% 的失败率大约等于长期多排队 5%**。这比 `quick` 的三倍惩罚轻得多——`quick` 的分数本身就是延时，失败不按超时计价就被淹没；`idle` 的分数是比例，“失败一次”和“慢一次”本来就是同一类事，数一次就够。

`idle` 的两个比例都要至少两次成功检查。只有一次时 `FLOOR` 就是那一次，两个比例都是 0，所有节点并列在最低分上，组只能随机挑；这一轮 `idle` 退回按延时排序。全部失败时成功延时未知，两个目标都记 `TIMEOUT`；一次都还没跑，就没有分数。

### 噪声：分数的不确定性

分数来自有限次检查，不是“这个节点永远的真实水平”，比较时也要把测量误差算进去。

换一批检查，分数和名次都可能变。这里的 `n` 是成功次数，失败比例的分母则是 `ALL`。

#### 单个节点的噪声估计

标准误差说的是：重测一遍，这个估计通常飘多少。均值的标准误差可以用样本标准差除以 `√n` 估；中位数这类以估计中心为基准的量，还得看数据分布。下面两个是本文用的近似值：

```
SE(score) ≈ √( (1.2533·sd(x)/√n)² + (1.858·sd(d)/√n)² )                     # quick
SE(score) ≈ 1000 · √( (1.2533·JIT/(FLOOR·√n))² + 0.5²·BAD(1−BAD)/ALL )     # idle
```

它们只是近似，不是精确的标准误差。用途只有一处：判断在用的节点是不是真的落后了，见[迟滞](#保留已有连接迟滞)。[容差带](#选择节点容差带)问的是另一件事——两个节点分不分得开——所以算法不同：`quick` 的带宽用 `JIT`，`idle` 只用 `PRES` 那一项。为什么，见 [`idle` 的余量为什么这么算](#idle-的余量为什么这么算)。

`quick` 那两项分别是 `MED` 和 `JIT` 的误差。`idle` 的两项来源不同：

- **一是 `PRES` 的误差。** `FLOOR` 是跨窗口留着的老值，这次窗口怎么抽都不动它，所以除下来以后，`PRES` 的误差就是 `MED` 的误差除以 `FLOOR`。而 `FLOOR` 取的是历史最快，噪声是单向的偏移，抽得再多也平均不掉，所以它不进标准误差，见[推导](#推导)。
- **二是 `BAD` 的误差。** `BAD` 是个比例——`ALL` 次尝试里有多少次没达标——按二项分布估，`√(BAD(1−BAD)/ALL)`。分母是全部尝试而不是成功次数，因为失败已经算在这一项里了。两项出自同一批检查，严格说相关，这里按独立处理，是个简化。

这些估计都假设检查彼此独立、窗口内分布大致稳定；样本少或趋势明显时尤其容易失准。

#### 两个节点分数差的噪声

要是两个节点的误差互不相干，差值的方差就是两者相加：

```
SD(score_node − score_best) ≈ √(SE_node² + SE_best²)
```

要是它们受同一个探测目标或同一段线路影响，误差会相关，差值里还得减去 `2·Cov`；这里当作零，是个简化。注意是平方相加再开方，不是把两个误差直接加起来，也不代表噪声被消掉了。

#### 为什么不能从分数里“减掉噪声”

噪声说的是“这个估计会飘多少”，不是固定的偏差，没法从分数里减掉一个通用数值。各指标的误差也各走各的：`MED` 和 `BAD` 的误差随 `1/√n` 缩小，`FLOOR` 在这个窗口里则一动不动。所以选节点时用**容差带**容纳不确定，而不是从分数里扣。

### 选择节点：容差带

分数和最好的差不多，就当一样好，免得为一点测量波动来回切。这个“差不多”由 `tolerance` 定；两个目标的默认值都是 `50ms`，因为分数都是毫秒——`quick` 的 50ms 就是 50ms，`idle` 的 50ms 相当于 1000ms 标尺上的 5%。

除了 `tolerance`，还要给“测量本身的波动”留位置，不然两轮之间的抖动就会被当成节点差异。分数都是毫秒，所以两个目标用同一个形状：

```
band = tolerance + 2√2 × 噪声_best / √n
cut  = score_best + band
```

`quick` 的噪声取 `JIT_best`；`idle` 取 `1000 × 1.2533·JIT/FLOOR`，只有 `PRES` 那一项——`BAD` 进分数，但不进带宽。两边都除以成功次数的平方根，也都用**典型偏差** `JIT` 去估 `σ`，不用 `sd(x)`：带宽的任务是把节点分开，被一次慢探测撑大的带宽会把所有节点都圈进来。系数 2 是经验值，不是说有 95% 的把握。

分数不高于 `cut` 的都留在候选里。样本越多，`1/√n` 那项越小，`band` 越靠近 `tolerance`，但不会小于它。成功次数不到两次时就不加噪声项，`band` 就是 `tolerance`。

#### `quick` 的余量为什么取 `JIT_best`

比的时候还不知道候选是谁、测得准不准，那就假设它和最好的那个一样准：

```
margin = 2 × √( (JIT_best/√n)² + (JIT_best/√n)² )
       = 2√2 × JIT_best/√n
```

为什么用 `JIT_best`：

- **不用 `DEV_best`。** `DEV` 是平均偏差，一次尖峰只占自己那一份，拿它估余量，会把“偶尔卡一次”的节点算得比实际稳；`JIT` 是偏差的中位数，几个异常值推不动它，更适合当噪声尺度。
- **不用完整的分数噪声。** 里面有平方离差，一次慢探测就能把它撑大，范围一宽，明显更差的也会进来。这是稳妥的取舍，不是数学上的下界。

#### `idle` 的余量为什么这么算

`idle` 的分数有两项，但带宽只由深度那一项决定。

**`PRES` 的误差。** `PRES` 等于 `MED` 除以 `FLOOR` 再减一，而 `FLOOR` 是跨窗口留着的定值，这次窗口抽成什么样都不改它。除以常数不改变相对误差，所以：

```
SE(PRES) ≈ SE(MED) / FLOOR ≈ 1.2533 · σ / (FLOOR · √n)
```

要估的是 `σ`，也就是单次检查的波动。这里用 `JIT`，不用 `sd(x)`：**带宽的任务是分辨**，而 `sd(x)` 会被一次慢探测撑大，宽到所有节点都算“差不多好”。

**`BAD` 不进带宽。** 它照常进分数，但带宽只由 `PRES` 的误差加 `tolerance` 构成。两层理由：

第一层是带宽要干什么。它问的是“这个节点有没有可能是和最好的一样好”，目的是别因为测量波动丢掉一个好节点。`PRES` 的偏差是抽样的噪声，方向对称，慢了一次不代表它慢，宽容它是对的。`BAD` 问的不是快慢，是**会不会坏**，两头代价不一样：放过一个会停顿的节点，代价是真实的坏请求；误杀一个好节点，代价只是少一个候选，而候选还有三十个。所以对不确定的频率，该要的是证据，不是放宽门槛。**不确定性不该让一个节点更容易被选中。**

第二层是小样本上的行为。`BAD` 是比例，二项标准误 `√(BAD(1−BAD)/ALL)` 在 `BAD` 为 0 时正好等于 0。要是把它加进带宽，带宽的宽度就取决于最好那个节点这一轮有没有恰好踩到一次坏检查，而不是取决于测得准不准——这显然不对。

`BAD` 的误差并没有丢，它还是用在[迟滞](#保留已有连接迟滞)里：那里面对的是一个已知节点，要的是别被一次波动打断，问的是“它可能差多少”，正好相反。两处各算各的，不共用。

余量是**绝对**的，不随分数大小变：常驻排队 10% 的节点和几乎不排队的节点，余量一样宽。这也让共用的 `50ms` 有意义——两个目标的分数都在几十到几百毫秒的量级，配置值和实际带宽处在同一把尺子上。样本越多，余量越小，这和 `quick` 一样。`FLOOR` 自己的不确定性比 `MED` 小，因为它由多个窗口汇总而来。

### 保留已有连接：迟滞

打开打断已有连接的选项后，节点被换掉时，原有连接还能暂时留着。刚离开选择范围的节点，只要超出的部分还在噪声余量内，就不急着断：

```
noise     = 2 × √(SE_node² + SE_best²)
allowance = band + min(band, noise)
```

这里比的是在用的节点和最好的节点，所以各用各自的噪声估计；计算时假设两者误差独立，共用探测目标或线路时可能相关，公式里没算。`min(band, noise)` 把额外保留限制在一个 `band` 以内，所以一个节点最多留到离最好**两个带宽**的地方。迟滞是为了扛住测量波动，不是长期留着明显更差的节点。

`idle` 的 `SE` 用完整的 `sd(x)` 估 `PRES` 的误差，带宽却按 `JIT` 算，两者能差一个数量级，于是 `min(band, noise)` 落在 `band` 上，保留范围就是**两倍带宽**。这正是封顶的用处——两个数答的不是同一个问题：一个问带宽要多窄才能分辨节点，另一个问这个已知节点的分数可能差多少。

`quick` 和 `idle` 的表现略有不同：`quick` 的噪声由延时样本的离散度和绝对偏差的离散度共同决定，样本越多越准；`idle` 的噪声由 `PRES`（跟着 `MED` 的误差）和 `BAD`（二项比例）合成，带宽只用前者，因为迟滞想知道的是“它可能差多少”。`BAD` 为 0 时后一项趋于零，所以完全干净的节点，误差只由 `PRES` 决定。

#### `urltest` 的单节点选择

`urltest` 一次只挑一个节点，没有负载均衡那层连接保留，迟滞直接放进选择里：在用的节点分数不超过最佳节点的 `Limit(best)` 时继续用，也就是最多容忍**一个带宽**的差距。

连接保留和节点选择是两件独立的事：前者决定要不要断已有连接，后者决定新连接能走哪些节点。

### 设计取舍：为什么不按标准差排序

样本标准差是常见的离散度指标，但不适合直接拿来当节点的波动分数，主要原因有三个：

1. **它以平均值为中心，而平均值会被离群值带偏。** 十次检查九次在 450ms、一次 3.15s，均值就从 450ms 被拉到 720ms，剩下九次的偏差凭空从 0 变成 270ms——尽管它们一次都没变。
2. **它把偏差平方，所以一个样本就能当家。** 同一个例子里，那一次检查贡献了九成方差，算出来描述的是这次探测，不是节点平时的样子。
3. **开方之后也回不到合适的尺度。** `n` 个样本里一个幅度 `X` 的尖峰，对平均偏差的贡献是 `X/n`，正好对上它拖慢的连接占比；对标准差的贡献却是 `X/√n`，`n = 10` 时就高出三倍多，窗口越长差得越多。

`DEV` 仍然算与中位数的偏差，但用线性平均，不让一个尖峰挪动中心。在 200ms 和 800ms 之间来回的节点照样有大的 `DEV`，它不是忽略不稳定，而是不让一个样本单独说了算。目前它只用于报告，不参与排序。

`idle` 的两个比例也都是线性的或计数的，不含平方：`PRES` 是比值，`BAD` 数的是次数，一个极端值只算一次。它们量的不是“窗口里忽快忽慢多少”，而是“比自己最好差了多少、差了几次”。这两件事在窗口里可能有同样的离散度，后果却不同：一个在 200ms 和 800ms 之间来回的节点，中位数约 500、地板还是 200，`PRES` 约 1.5、`BAD` 约一半；一个稳定在 800ms 的节点，地板也是 800，两个比例都是零——它从没更快过，所以现在这个慢不是排队。**`idle` 选后者。** 稳定的慢是可以用 `max_rtt` 处理的已知成本，忽快忽慢不是：同一段流量时快时慢，没法预先安排。

标准差并没有被完全排除：`quick` 还用样本标准差估分数噪声，只是不把它直接当排序分数。

### 设计取舍：为什么趋势不直接进入分数

窗口里的样本有先后顺序，可上面这些统计量都不看顺序：怎么打乱，`MED`、`PRES`、`BAD`、`JIT`、`DEV` 都不变。所以一个持续变差十分钟的节点，只要延时分布相同，读数和一直就这个样子的节点一模一样。

`PRES` 和 `BAD` 补了一部分，但方式不同：它们比的不是窗口里的先后，而是**现在和历史最好**。从 200ms 变到 600ms 的节点，`MED` 立刻是 600，`FLOOR` 还是 200，`PRES` 立刻变 2.0，不用等趋势攒出来；从 600ms 变回 200ms 的节点，`FLOOR` 跟着降到 200，`PRES` 马上回到接近零，也不会被过去的坏状态拖着。**方向因此不用单独处理：`FLOOR` 只会往下走，变好立刻认，变差立刻兑现。**

比较前后半窗（`median(后半) − median(前半)`）确实能多看出点东西，算起来也很便宜，能分辨“刚开始变差”和“已经差了一阵子”。但趋势没进分数，是因为一进来，`interval` 一变排名就会变。排名该反映节点本身，不该取决于多久查一次。趋势属于决策，和容差是一类东西，不属于测量结果。

它还得小心用：`sampling` 是 10 时，后半窗五个样本里连着两次异常推不动中位数，要到第三次才看得见。这样它比“最近一次检查”还慢，而后者本来就在统计量里。

窗口长度也是同一笔账：延时分布大体稳定时，窗口越长越平滑、噪声越小；可旧样本占的比重也越大，节点变了分数跟得越慢。缩短窗口跟得更紧，也更容易被偶然波动带着走。降低噪声和跟上变化，是同一个窗口选择的两头。

### 设计取舍：基线为什么排成一圈格子

基线记的是“这个节点最好的样子”，它同时被两个相反的要求夹着：**要记得够久**，因为空载只出现在日低谷，看得太短就把拥堵时的水平当成空载；**又要忘得掉**，因为同名节点可能换了线路、换了机器，旧基线立刻就是错的。

单独设一个“什么时候过期”的计时器很难两头兼顾，因为过期是一次性事件：到期前什么都不变，到期那一刻全变。切成格子就没这个问题：

```
48 格 × 30 分钟 = 24 小时
每 30 分钟只有一格被重置，其余 47 格照旧
```

- **记得够久**：一圈盖住 24 小时，每个时段都有自己的记录，基线随时有完整一天作参考。
- **忘得平顺**：没有“过期”这个动作，只有一格被下一次同格记录盖掉。基线不会在某一瞬间整体作废，也不会因为一次重置让全组的分数同时归零。

格子按墙上的钟切，不按运行时长切，所以第 40 格永远是 20:00 到 20:30。这样每格记的是**节点在这个时段最快能有多快**，而不是随便 24 小时里的最低值。

格子多少决定了记录的时间粒度，也决定每格能放几次探测：格子少，每格盖的时间长，一个时段里的起伏都压成一个最小值；格子多，每格里的探测就少，记录可能只由一两次决定。48 能整除一天，每格也装得下好几轮检查，所以选了它。它跟 `sampling`、`interval` 是一类的，改了要一起考虑探测频率，不适合单独给用户配。

**代价。** 地板是“每格里最小值”再取最小，仍然是个最小值，偏向记最乐观的那一次。这跟它的用途是一致的（要的就是空载水平），但也意味着偶尔一次走运的探测会把地板压得略低，让每个节点的 `PRES` 都偏大一点，见[推导](#推导)。这个偏差是**大家一样**的，不改变名次，只影响 `tolerance` 相对的严格程度。

#### 更新、过期与启动

**更新。** 每轮先更新格子，再算分数，所以这一轮的观测立刻生效：

```
slot[k]  = min(slot[k], MIN)               # 进新格时先重置为 MIN，再取格内最小值
FLOOR    = min(最近 24 小时内各格的值)
PRES     = max(0, MED − FLOOR) / FLOOR
BAD      = (#{xᵢ > 2 × FLOOR} + FAIL) / ALL
```

先更新不会让分数归零：每格存的是最小值，更新后 `FLOOR ≤ MIN ≤ MED`，`PRES` 还是非负的比值，`BAD` 还是个占比。反过来先算分再更新，节点变快就要等到下一轮才反映出来，没有好处。

**过期。** 没有单独的过期步骤：24 小时后，同一格会被下一轮记录覆盖，旧记录随之失效。所以基线永远来自**真正测过的时段**，不会像“到期就重置成当前值”那样，把眼下的拥堵误当成最快水平。某个时段一直拥堵，那个时段的记录会慢慢变高，别的时段照旧；只有长期都堵，整体基线才会升高，等于承认“这节点平时就是这样”。

**跳变。** 节点平稳或缓慢变化时，基线每次只移动一格带来的变化量，因为 30 分钟只换一格。以每天慢 144ms 的节点为例：一次性过期是 144ms 的突变；用格子之后，这个变化摊到一天的 48 次更新里，每次约 11ms。**不过，突发变化（换线路、换机器）还是会跳一下**：最后一格旧数据被覆盖时，最小值只能落到下一个最小值，跳的幅度就是变化本身。这是忘掉旧数据要付的代价，不是平滑能消掉的噪声。

**启动。** 第一轮写入的就是这一轮最快值，所以 `FLOOR` 一开始就是 `MIN`，不需要单独的降级处理。之后地板从一格开始慢慢填满，铺满一天要 24 小时。开了缓存时，重启会把整天的格子和长期失败率接着用；缓存不可用（没开、检查的目标或链路变了、记录过期了）就跟冷启动一样，从零开始攒。这期间每格盖的时段少，地板容易偏高——这是忘掉旧数据的代价，排序仍然成立，理由见[为什么两个分项都是比值](#设计取舍为什么两个分项都是比值)。

### 设计取舍：缓存为什么只存地板和失败率

窗口之外的跨轮次状态只有两样：基线和长期失败率。窗口只有 `sampling` 次检查（`sampling × interval`），而它们一个要看 24 小时，一个要看 `τ = 45` 分钟。重启的代价因此极不对称：窗口几分钟就重建好了，`FLOOR` 要等下一个日低谷，`FAILR` 要等节点**再失败一次**才有证据。

窗口里的样本不存——二十来分钟就能重建，而要留住那几百次检查，空间要多两个数量级。

**记录按“路径 + 节点”算，不按检查算。** 记的是“这个节点经这条路走”的样子：目标或链路不同就各记各的；目标与链路相同、只有窗口或间隔不同的两个检查，会共享它们共同那几个节点的记录。这样分享够精确——同一条路径上，一个窗口采样两次和一天采样一百次，最后每个节点的地板是同一个值，两边差的只是噪声，不是来源。写入的一方只动自己测过的节点，读回来的值描述的就是节点本身。

记录只在 24 小时内有用，也就是地板能活多久；过了这个时间的记录会被丢掉，所以一个再也不被检查的节点不会永远占着位置。

### 设计取舍：为什么阈值是两倍，权重是 0.5

`BAD` 的判据是“慢到自己最好水平的两倍”，权重 `0.5` 让一个“每次都翻倍”的节点在标尺上加 500。两个数都不是拟合出来的，各有各的道理。

**为什么是两倍。** 两倍就是“耗时翻了一番”，也是最常用来判断一条线路开始排队的门槛。定得太低（比如 1.5 倍），正常的抖动和探测波动也会越线，每个节点都带着一截 `BAD`，彼此就分不出来了——这一项本来要区分的是“偶尔排队”和“一直排队”。定得太高（比如 3 倍），只有持续的长队够得着，几乎所有节点都归零，这一项等于不存在，分数退回去只看深度。两倍落在中间：正常波动够不到，真排队一定越得过去。

**为什么是 0.5。** 它把“频率”换算到和“深度”同一把尺子上。`PRES` 的量级在 0 到 1 之间，而一个“每次都翻倍”的节点，应该被判得和最糟的常驻排队差不多差，也就是加一个接近 1 的量。取 0.5，意味着“每次翻倍”比“常驻排队 50%”稍重一点。这个量级是判断，不是拟合。

它也不是随手取的，但不需要精细调——它定的是**换算率**：几次坏检查等于一个百分点的排队。换算率一变，边上的节点就换人：宽一点，多收一两个只是略差的；窄一点，只留最干净的。所以这是个策略问题——你希望“偶尔卡一下”在多大程度上等价于“一直慢一点”。明显不同的节点之间，先后不取决于这个数，只有卡在带宽边缘的那几个会。

这两项**必须分开**，因为它们抓的是不同的毛病：

| 节点 | `PRES` | `BAD` | 只按深度排 | 只按频率排 |
| --- | --- | --- | --- | --- |
| 快但常掉线 | 很低 | 很高 | 第一 | 中游 |
| 慢但很稳 | 中等 | 很低 | 中游 | 第一 |
| 又慢又常掉线 | 很高 | 很高 | 垫底 | 垫底 |

只用其中一个，另一类明显的毛病就会被放过。

### 设计取舍：为什么两个分项都是比值

`idle` 要回答“这节点比自己最好的时候差多少”，而“差多少”有两种写法：差值（`MED − FLOOR`）和比值（`(MED − FLOOR) / FLOOR`）。选比值不是偏好，是唯一能把距离去掉的写法。

**差值会把距离带回来。** 一个 400ms 的节点地板 380，多等 20ms；一个 900ms 的节点地板 860，多等 40ms。按差值后者更差，可那 40ms 里有一部分是它天生更远：同样的排队程度，线路越长，多出来的毫秒越多。差值分不开“我在排队”和“我天生远”，因为它本身就带着地板的量纲。比值把地板约掉了：`PRES` 是“多等的部分占自己地板的比例”，同样的排队程度，远近节点是同一个数；`BAD` 只跟自己地板比，也不带距离。两项都无量纲，这才叫“与距离无关”。

**代价要认，但名次不会乱。** 比值会放大低地板的噪声：分母小，同样的绝对误差算出更大的比例。所以地板不能按节点错得离谱——这正是格子在管的事。地板错得“大家一样”时名次也不动：地板错多少，`PRES` 就等比例缩放多少，`BAD` 也按同一地板重算。这跟差值形式有本质区别：差值里地板错 10ms 就是平移 10ms，直接改名次。

只有**不同节点**的地板错得不成比例时名次才会动，而地板偏差的两个来源都不针对谁：一是取最小值带来的系统性偏低，所有节点朝同一方向偏；二是每个节点的地板落在哪个采样值上，这取决于它自己的分布宽度，分布窄的很快收敛到真实下限。所以地板还没攒满的时候，分数整体偏乐观一点，`tolerance` 相对的严格程度跟着变一点，名次不变。

**边界在哪？** 地板误差越大，比值形式越吃亏：分母被噪声放大到一定程度，它就和差值形式打平。换机器、换线路会让旧地板彻底失效，这正是那圈 24 小时格子要处理的事。还有一处耦合值得记下：波动越大的节点地板压得越低，`PRES` 就被抬高——波动大本身就是毛病，方向和设计意图一致，但它意味着 `PRES` 里混了一部分波动信息，和 `BAD` 有重叠；好在重叠方向一致，不会让安静的节点因为“看起来波动大”而占便宜。

### 推导

这节解释噪声估计里那些公式、常数和假设。先约定记号：

- `n` 是成功检查的数量；`xᵢ` 是第 `i` 次成功检查的延时；`MED` 是这些延时的样本中位数。
- `sd(…)` 是样本标准差，用来估一批数据通常离开中心多远。
- `Var(…)` 是方差，波动大小的平方；`SE`（标准误差）是估计值在重复采样时通常飘多少，等于方差开平方。
- `SE` 在这里是近似值，不是精确的标准误差或置信区间。

下面的推导假设检查彼此独立，且来自一个采样窗口内稳定的分布；分析 `JIT` 时还假设分布对称。真实网络不一定完全满足。

#### `idle`：两个比例的误差估计

`idle` 按 `score = 1000 × (PRES + 0.5 × BAD)` 排序，要估的是：重做一批检查，这个和通常变多少。

**`FLOOR` 在一轮之内是常数。** 它由各格最小值汇总而来，本轮写完就是个定值；减它是减常数，除以它也是除以常数。所以两个比例各自只随窗口内的量变化：

```
Var(PRES) = Var(MED / FLOOR) = Var(MED) / FLOOR²
```

本轮写入可能让 `FLOOR` **下移**（这一轮出现了更快的一次），这时 `PRES` 的参照变成 `MIN`，还多带一点 `MIN` 的噪声。但这只在刷新记录时发生，方向单一，不是每轮都有的抖动，所以噪声模型仍以 `MED` 为主。

`FLOOR` 自己的偏差是另一回事，它是**系统性的**：最小值偏低，每个节点的 `PRES` 都朝同一方向偏大，抽得再多也平均不掉，所以进不了标准误差，只能靠理解它的方向对待，见最后一步。

**`MED` 的方差。** 中位数只看样本的排序位置，方差取决于中位数附近的概率密度 `f(m)`：`Var(MED) ≈ 1/(4n·f(m)²)`。正态近似下 `f(m) = 1/(σ√(2π))`，代入得 `(π/2)·σ²/n`，开方即

```
SE(MED) ≈ 1.2533 · σ / √n
```

`σ` 是单次检查的波动。它有两条估法：`sd(x)` 是样本标准差，标准误差的原始定义就用它；`JIT` 是偏差中位数乘 `1.4826`，同一刻度的稳健估计，推不动的是尖峰。迟滞用前者，余量用后者，理由见 [`idle` 的余量为什么这么算](#idle-的余量为什么这么算)。

**合起来就是 `PRES` 的误差**（余量里再把 `sd(x)` 换成 `JIT`，形状不变）：

```
SE(PRES) ≈ SE(MED) / FLOOR ≈ 1.2533 · sd(x) / (FLOOR · √n)
```

这是**绝对**误差，不随分数大小变：常驻排队 10% 的节点和几乎不排队的节点，误差尺度一样——它们只差在 `MED`，而误差只取决于 `σ`、`FLOOR` 和 `n`。

**`BAD` 的误差。** 它是 `ALL` 次尝试里没达标的比例，一个二项比例：

```
SE(BAD) ≈ √( BAD(1 − BAD) / ALL )
```

它不依赖 `σ`，只看 `BAD` 和尝试次数；`BAD` 为 0 时它也是 0，正是这一点让它能进迟滞、却不能进带宽。分母是全部尝试而不是成功次数：失败已经算在分子里，用更小的分母会把误差算窄，而失败多的节点恰恰是误差该大的那个。

两项出自同一窗口，严格说相关；这里按方差相加，把相关当作零：

```
SE(score) ≈ 1000 · √( SE(PRES)² + 0.5² · SE(BAD)² )
```

这是**迟滞**用的噪声估计。带宽只用 `PRES` 那一项：

```
带宽的余量 = 2√2 · 1000 · 1.2533 · JIT / (FLOOR · √n)
```

**最后一步：`FLOOR` 取最小值，所以偏乐观。** 一天里探测机会很多，总有一次走运，于是最小值系统性偏低（机会越多偏得越多，这是极值本身的规律）。代价是每个节点的 `PRES` 都大几个百分点，换来的是这个量**不迟钝**。

换成按窗口中位数记，会安静得多，但它回答的是另一个问题：“这节点**通常**有多快”。平稳时段里每个节点的中位数都等于它自己，`PRES` 全是零，`idle` 就没得排了。更糟的是有一类真实节点：延时在两个带宽池之间轮换，两低两高时中位数正好落在两峰中间——一个它从未达到过的值，而且逐轮都稳，于是它被读成最稳的一个。取最小值就不会被这种结构骗到。

这个偏差**大家一样**，不改变名次：两个节点都偏乐观同样的比例，它们在 `PRES` 上的差仍然是真实差距的差。它只挪动零点，也就是 `tolerance` 相对的严格程度。

#### `quick`：`MED` 的误差

`quick` 的分数是 `MED + JIT`。先看 `MED`：换一批检查，中位数也会动。动多少取决于中位数附近有多挤——样本扎堆在那儿，中位数就不容易被推走；附近稀疏，少量样本变化就能让它跳得远。

用 `f(m)` 表示总体中位数 `m` 附近的概率密度，可以理解成“延时落在中位数附近的密集程度”。样本较多时，中位数的方差近似为：

```
Var(MED) ≈ 1 / (4n·f(m)²)
```

对正态分布，`f(m) = 1/(σ√(2π))`，代入后：

```
Var(MED) ≈ (π/2)·σ²/n
SE(MED)  ≈ √(π/2)·σ/√n
          ≈ 1.2533·sd(x)/√n
```

这里用样本 `sd(x)` 估总体标准差 `σ`。所以 `1.2533 = √(π/2)` 是**正态分布近似**下的系数，换成别的分布要重新推。

#### `quick`：`JIT` 为什么乘 `1.4826`

`JIT` 用绝对偏差的中位数表示“典型波动”，再乘 `1.4826` 换到和标准差同一刻度。这个常数来自正态分布：

```
q = median(|X − m|)
P(|X − m| ≤ q) = 1/2
```

对称的正态分布里，“落在 `m` 左右 `q` 以内”占一半概率，所以从均值到 `m+q` 是四分之一，即 `Φ(q/σ)=0.75`。于是：

```
q = Φ⁻¹(0.75)·σ ≈ 0.6745·σ
σ ≈ q / 0.6745 ≈ 1.4826·q
1.4826 = 1 / Φ⁻¹(0.75)
```

也就是说，正态数据下偏差中位数约为 `0.6745σ`，乘上 `1.4826` 就回到了标准差的尺度。它是正态分布下的换算常数，不代表实际延时一定服从正态分布。

#### `quick`：`JIT` 的误差估计

就算知道真实中心 `m`，`JIT` 也会因为抽到哪批样本而变。设 `q` 是 `|X−m|` 的总体中位数，`g(q)` 是绝对偏差在 `q` 附近的概率密度。中心已知、分布对称、样本够多时：

```
SE(median(|X − m|)) ≈ 1 / (2g(q)√n)
SE(JIT) ≈ 1.4826 / (2g(q)√n)
```

直观上，`q` 附近的绝对偏差越密集，中位数越不容易动，误差越小。要是中心也得从同一批样本估，或者分布不对称，还得再考虑这些影响。

本文用 `1.858·sd(d)/√n` 估这一项，其中 `1.858 = 1.4826 × 1.2533`。这相当于把正态中位数的系数套在 `d` 上；可即使 `x` 服从正态，绝对偏差 `d` 也是半正态分布，所以 `1.858` 不是严格推出来的标准误差系数。它是个估计值，不是精确的概率保证。

#### `quick`：合并 `MED` 与 `JIT` 的误差

两个量的误差独立时，它们之和的方差就是各自方差相加；一般情况下还要加上协方差项：

```
Var(MED + JIT) =
    Var(MED) + Var(JIT) + 2·Cov(MED, JIT)
```

`MED` 和 `JIT` 用同一批样本算，原则上可能相关。对称 IID 分布下它们渐近独立，所以这里近似忽略协方差；有限样本或别的分布下不一定成立。合成后的噪声估计是：

```
SE(score) ≈ √( SE(MED)² + SE(JIT)² )
```

所以 `quick` 里的系数和方差合成，依赖上面这些分布和样本假设；这个 `SE` 是估计，不是 95% 置信区间。

#### 两个节点比较时，差值有多不确定

要问的是：重测一遍，节点分数与最佳分数之差会飘多少。把两个分数看作随机量：

```
S_node   = 节点分数的随机量
S_best   = 最优节点分数的随机量
D        = S_node − S_best
Var(D)   = Var(S_node) + Var(S_best)
           − 2·Cov(S_node, S_best)
```

两个节点的误差独立时，协方差为零。若共用探测目标或受同一段线路影响，它可能不为零，这里忽略。独立假设下把上述噪声估代入再开方：

```
Var(D) ≈ SE_node² + SE_best²
SD(D)  ≈ √(SE_node² + SE_best²)
```

`SD(D)` 是差值重测时的波动；式中的 `SE` 都是估计值，不是精确值。

#### `SD` 与 `SE` 是什么关系

`SD`（标准差）描述一个随机量本身怎么波动；`SE`（标准误差）描述一个估计值在重复采样时怎么波动。分数是拿样本算出来的估计值，所以它的标准差就是它的标准误差。这里用 `SE` 表示对这个误差的近似。

`score_node` 和 `score_best` 在当下窗口里已经是定值；把它们当随机量，是在问“要是重新测一遍，它们可能差多少”。

#### 长期失败率

`max_fail` 默认是 `0`，所以只有当前窗口没失败的节点才进得来候选。这样一来两个分数公式里的 `FAIL / ALL` 都是零：失败项只在节点被排除之后才起作用，反映不了候选的潜在风险。

可窗口干净，不等于接下来不会失败。节点的失败方式差别很大：一类是**碎抖**，失败零散摊在历史里，随时可能再掉；另一类是**长故障**，连续掉线一次之后长时间干净。两类的历史失败率可能差不多，但窗口一干净，碎抖型下一次失败来得快得多。十次检查的窗口看不出这个区别。

所以另记一个跨轮次的 `FAILR`，和窗口内实测失败率取大的那个进分数，见上面的 `p` 和 `BAD`。

**为什么按时间衰减，而不按次数。** 按次数统计的话，`sampling`、`extra` 都得指定保留多少次，而间隔 `1m` 和 `5m` 下同样的次数对应的时长差五倍，这个差别会进到分数里。按时间算就没这个问题：两个 1 分钟间隔和一个 2 分钟间隔，时长一样衰减一样，调 `interval` 时也不用重新理解这个估计。它也不受运行时改采样影响，窗口重采样不会把它清零。

**为什么不统计一整天。** 一天的失败率会把晚高峰和平稳时段混在一起，可排队和掉线随时段变化。按 `τ` 衰减能跟着近期走：晚高峰时反映晚高峰，不被一天的平均值冲淡。

**τ 取多久。** 数据给不出标准答案：把统计范围放大很多倍，对判断之后会不会失败帮助也很小。只能在两头取平衡——既要较快淡化已经结束的故障，也不能被一次偶发失败带偏。取 45 分钟：一个节点连续失败 54 分钟后恢复，一小时之后就不该再为这次故障扣分。

**它有多重要。** 分辨力远不如延时，主要用在延时接近时打破平局，区分“又快又常掉线”和“稍慢但稳定”，不会动摇“快的还是快”。

`失败 / 总数` 是**等权平均**：窗口里每次检查权重相同，一离开窗口，权重从 `1/n` 直接变成 `0`。于是窗口边界上会突变，间隔不同时同一个次数对应的时长也不同。

`FAILR` 换了平均法：**越近的权重越大，越久的越小，权重只看经过的时间**。设检查 `i` 发生在 `tᵢ`，当前时刻 `t`：

```
wᵢ = exp(−(t − tᵢ) / τ)
R  = Σ wᵢ·xᵢ / Σ wᵢ              # xᵢ = 1 表示这次失败
FAILR = R
```

**为什么非得是指数。** 权重只看过了多久，而且前后两段能合并：`w(a + b) = w(a) · w(b)`——先过 `a` 分钟再过 `b` 分钟，应该和一次过 `a+b` 分钟一样。连续又不恒为零的函数里只有指数满足这条，所以 `w(t) = exp(−t/τ)`。换成线性衰减、阶梯衰减或固定次数的滑动窗口，同一个 `τ` 在 `1m` 和 `5m` 下代表的时长就不一样了。

**递推。** 记 `c = exp(−Δt/τ)`，每来一次新检查旧权重都乘 `c`，所以只要累计两个量：

```
S ← c·S + x          # 加权失败次数
W ← c·W + 1          # 加权检查次数
R  = S / W
```

只存 `R` 不存 `W`，间隔固定时也算得对；分开存是为了冷启动能带先验。检查越密，`W` 的稳态 `τ/Δt` 越大，每次检查的影响越小——这正是“这一次只代表一小段时间”。

**冷启动的先验。** `W` 的初值取 10，相当于“十次干净检查”：冷启动是“没见过它失败”，不是“见过它失败”。要是从零开始，第一条检查就是全部证据，一次失败能把 `R` 顶到 `1.0`——进程刚起来、网络还没就绪时每个节点的第一次检查都会失败，那样每个节点都要背着接近满分的估计走一小时。先验也按 `c` 衰减，历史一长就可以忽略。开着缓存时，恢复的历史直接取代这个起点。

**它和 `失败 / 总数` 差在哪。** 失败率一段时间内不变时，`R` 最后也会接近它，两者结果一样；只有失败率变化时才分家：前者在窗口边界突变，后者按 `exp(−t/τ)` 慢慢降。以 `τ = 45 分钟`、每分钟查一次为例，一个此前一直正常（`R ≈ 0`）的节点连着失败 10 次，此后全部成功：

| 之后又连续成功 | 窗口 `失败 / 总数`（10 次采样） | `R` |
| --- | --- | --- |
| 0 分钟 | `10/10 = 1.000` | `0.199` |
| 10 分钟 | `0/10 = 0.000`（跳变） | `0.160` |
| 45 分钟 | `0/10 = 0.000` | `0.073` |
| 90 分钟 | `0/10 = 0.000` | `0.027` |

表里假定此前历史够长、先验早已淡出：第一行是 `1 − exp(−10/45)`，之后每过一段乘 `exp(−Δt/45)`。窗口在第 10 分钟就不记这次故障了，`R` 还要一个多小时才落回去——这就是要用 `FAILR` 而不是只看 `FAIL / ALL` 的原因。

**相当于用了几次检查。** 权重总和 `1/(1 − c) ≈ τ/Δt`，也就是大致相当于过去 `τ/Δt` 次检查：间隔 `1m` 约 45 次，`2m` 约 22 次，`5m` 约 9 次。间隔越长，同一个 `τ` 盖住的检查越少，估计越粗，所以 `τ` 不能太短。

### 调试

想在自己的线路和负载下核对这套估计，直接问 API（组名是中文要 URL 编码）：

```bash
curl -s 'http://127.0.0.1:9090/private/health/Name/windows?ahead=2&configs=1:5,1:10,2:5'
```

`rho` 比的是全体节点的名次，`agreement` 比的是 pool 的成员——负载均衡从整个 pool 里取连接，pool 一样就是一样，内部谁排第一不影响。窗口越长，`rho` 未必越高：它会把节点早先的状态混进对紧接着几次检查的预测里。`agreement` 奖励稳定，`reaction` 和 `recovery` 报的是这份稳定的代价。窗口要「`样本数 × stride` + `ahead`」次检查才测得出来，而组默认只留 `sampling` 次。要让采样数和保留次数就地调整、不必重启，已收集的检查也不会丢：

```bash
curl -X PUT 'http://127.0.0.1:9090/private/health/Name/history?sampling=15&extra=60'
```

`sampling` 是算法采纳的次数，省略则保持当前值；`extra` 是采样数之外多留的次数，只用于诊断，省略或给 `0` 就只留采样数。

参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `ahead` | `8` | 窗口要预测其后多少次检查 |
| `configs` | 默认网格 | `stride:samples` 列表，如 `1:15,2:10`。`stride` 是隔几个检查取一个，`samples` 是窗口里的样本数 |

字段

| 字段 | 说明 |
| --- | --- |
| `interval` | 检查记录的实际间距（中位数），不是配置里写的值 |
| `nodes` | 参与测量的节点数 |
| `checks` | 最长的那份历史有多少次检查 |
| `ahead` | 每个窗口被要求预测其后多少次检查 |
| `stride` | 隔几个检查取一个，`1` 为连续 |
| `samples` | 窗口里的样本数，窗口跨度为 `interval × stride × samples` |
| `span` | 窗口的实际宽度 |
| `windows` | 该窗口在历史上被摆放的位置数，其余字段是这些位置的平均 |
| `rho` | 窗口排出的顺序与其后检查排出的顺序的秩相关：`1` 完全一致，`0` 等于瞎猜。饱和后没有分辨力，只作历史太短时的参考 |
| `delta` | `rho` 的标准误差；`windows` 少时会塌成 `0`，那是没有精度可言 |
| `pool` | 该窗口下 band 平均放进来几个节点 |
| `agreement` | 窗口选出的 pool 与其后检查选出的 pool 的 Jaccard 相似度：`1` 是同一批节点，`0` 是没有一个相同 |
| `exact` | 两个 pool 完全相同的位置占比；`agreement` 把部分重合也算作相似，`exact` 只认完全一样 |
| `reaction` | 节点变慢之后，窗口要几次检查才把它移出 pool；`ahead + 1` 表示到视界尽头仍在 pool 里，没有 `reactions` 时不出现 |
| `reactions` | 历史上“正在被使用、随后变慢”的次数；失败不算，因为失败在当次检查就被剔除 |
| `recovery` | 反方向的同一件事：节点恢复之后，又要几次检查才重新进入 pool。视界取窗口宽度（`samples × stride`），因为失败要先离开窗口；视界内没回来记为“视界 + 1”，没有 `recoveries` 时不出现 |
| `recoveries` | 历史上“正在被使用、被剔除后又恢复”的次数 |
| `note` | 一个窗口都测不出来时，说明还差多少 |
