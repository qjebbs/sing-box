# 节点评分

本页说明组如何根据[健康检查](/zh/configuration/shared/health-check/)结果给节点排序，以及这些规则的用意。

### 评分目标：绝对的速度，与相对的质量

评分前先确定目标。组会选择其中一个，不把两种目标混成一个分数：

- `quick`：**节点通常有多快？** 170ms 的节点通常比 40ms 的节点更慢。这是绝对量，以毫秒计。
- `idle`：**这个节点比它自己做得到的差多少？** 一个平时 200ms、晚高峰长期 600ms 的节点，即使 600ms 不算慢，也已经在自己能力的四倍上运行，会拖慢高峰时的每一段流量。

两者回答的问题不同，**单位也不同**：`quick` 比的是实际延时，`idle` 比的是节点相对自身最好状态的退化。若用实际延时衡量退化，较远的节点会天然吃亏，比较的就成了距离，而不是状态。因此，`idle` 使用的都是比例，不受节点远近影响，见[设计取舍](#设计取舍为什么两个分项都是比值)。

### 统计量：从成功检查中计算

延时统计只看**成功**的检查。失败检查通常会等到超时，不能说明节点正常工作时有多快。失败次数和检查总数另行记录，用于判断节点是否合格，以及计算 `quick` 的失败惩罚。

记 `x₁ … xₙ` 为本窗口内成功检查的延时，`n` 为成功次数，`dᵢ = |xᵢ − MED|` 为每次检查与中位数的绝对差：

```
MED     = median(x₁ … xₙ)      # 本次窗口的延时中位数
JIT     = 1.4826 × median(dᵢ)  # 典型偏差
DEV     = (1/n) × Σdᵢ          # 平均偏差
```

`MED`、`JIT`、`DEV` 都根据当前窗口计算，窗口更新时也会随之更新。另有一个会跨轮次保留的参考值：

```
SLOT     = 30 分钟一格，共 48 格，覆盖 24 小时
SLOT[k]  = 第 k 格内见过的最快一次延时
FLOOR    = min(最近 24 小时内各格的值)         # 这个节点最好能做到多快
PRES     = max(0, MED − FLOOR) / FLOOR      # 排队量：典型延时比它自己最好时多等了百分之多少
BAD      = (#{xᵢ > 2 × FLOOR} + FAIL) / ALL # 排队频率：多大比例的尝试没达到它自己能做的水平
```

以上公式适用于至少有两次成功检查的情况。只有一次成功检查时，数据不足以估计波动，`JIT` 与 `DEV` 都取该次延时的一半，避免把“样本不够”误当成“完全没有波动”。两个比例此时也无从计算——`FLOOR` 就是那一次延时本身——所以 `idle` 改用延时本身排序，见[分数](#分数延时与排队)。没有成功检查时，就没有延时统计量。

- `SLOT` 按墙钟时间划分：`k` 表示当前时刻属于当天的第几个 30 分钟，因此每格总对应一天中的同一时段。进入新的一格时，先用本轮最快的延时更新它；之后只保留这一时段内的最小值。24 小时后，同一格会被下一次记录覆盖，旧值也就自然失效。
- **`MED`** 是延时水平。用中位数而不是平均值，可以减少单次慢检查的影响。
- **`JIT`** 表示**通常的波动幅度**。少数尖峰通常不会明显影响它；`1.4826` 是在正态分布假设下，将偏差中位数换算到标准差刻度的系数。
- **`DEV`** 表示**整体波动代价**。每次检查都会计入：偶发尖峰贡献较小，出现越多，累积影响越大。它仍会显示在报告中，方便排查，但不参与排序。
- **`FLOOR`** 是**观测到的最快延时**，不做平滑。一次碰巧很快的探测会把它压低，让节点之后看起来一直有少量排队；但它也能及时反映变化。
- **`PRES`** 表示排队压力，是当前延时比**节点自己最好时**高出的**比例**。除以节点自己的地板后，传播延迟的影响会抵消，因此这个比例不受节点远近影响。
- **`BAD`** 表示排队的**频率**：延时超过自身最好水平两倍的检查占比，加上失败检查的占比。它只和地板比较，不受节点远近影响；一次极端延时也只算一次。

### 分数：延时与排队

两个目标的公式不同，因为失败在两个目标里的位置不同。

`quick` 的分数表示节点通常带来的延时成本，成功和失败检查按各自所占比例加权。记 `ALL` 为检查总数，`FAIL` 为失败数，`TIMEOUT` 为健康检查的超时时间：

```
base    = MED + JIT
cost    = min(TIMEOUT, base)
failure = min(TIMEOUT, 3 × cost)
score   = (ALL - FAIL) / ALL × cost + FAIL / ALL × failure
```

通常延时更低、常见波动更小的节点，得分也更低。波动按毫秒计入延时成本。

`cost` 是成功检查的基础分数，`failure` 是失败检查的惩罚。一次失败最多按成功成本的三倍计入，且不超过 `TIMEOUT`。这是评分规则，不是对实际重试耗时的精确测量。如果每次失败都按完整超时时间计分，一次失败就可能压过所有未失败的节点。

`idle` 的分数是排队深度与排队频率之和，失败只在频率里计入：

```
score = 1000 × (PRES + 0.5 × BAD)
```

`0.5` 是 `BAD` 的权重，`1000` 是把无量纲结果折算成毫秒的标尺。两者都不是从数据里拟合出来的，理由见[设计取舍](#设计取舍为什么阈值是两倍权重是-05)。

这里不比较延时本身：平时 400ms 和 100ms 的节点，都可能有九成检查接近自己的地板；平时 100ms、每三次就有一次超过地板两倍的节点则不是这样。分数相同时，优先选择 `spread` 较小的节点。

**为什么乘 1000。** `PRES` 与 `BAD` 都是比例，乘 1000 后就能按毫秒显示。这样两个目标的分数单位相同，可以共用 `tolerance` 字段和默认值：

| 目标 | 分数 | `tolerance` 默认 | 含义 |
| --- | --- | --- | --- |
| `quick` | `MED + JIT`（绝对毫秒） | `50ms` | 50ms 的差距不值得切换 |
| `idle` | `1000 × (PRES + 0.5 × BAD)` | `50ms` | 5% 的相对退化不值得切换 |

同一个 `50ms`，在两个目标里都表示“不值得为这点差别切换”。日志和报告也都用毫秒显示分数，不必记两套单位。

失败怎样计入分数？它只进入**频率**，每次失败都算一次坏检查，见上面的 `BAD`。它不能进入**深度**：`PRES` 是比例，失败没有可比较的延时。若把 `TIMEOUT` 当作失败的延时，三十次检查里的一次失败就会让 `PRES` 增加 0.8（约 800ms），盖过正常的排队差异。这和过去按 `3 × DEV` 折算失败的问题相同：**排队延时和失败代价不能直接换算**。

需要接受这里的换算：`BAD` 每增加 10%，分数增加 50ms。因此，**10% 的失败率大致相当于长期多排队 5%**。这比 `quick` 对单次失败的三倍惩罚轻：`quick` 的分数是延时的量级，一次失败必须按超时去计价才不会被淹没；`idle` 的分数是比例，失败和“慢一次”本来就是同一种东西，数一次就够。

`max_fail` 因此不再是唯一挡住失败节点的机制，但它仍然是**必要的兜底**。它管的是这一窗口里“一次失败都不能有”，`BAD` 管的是长期比例，两者回答的不是同一个问题：一个节点可能在整个窗口里都没失败、比例也很好看，却周期性掉线，而十次检查的窗口看不出这一点。所以默认值仍是 `0`：不配置时，有失败的节点只属于 `alive` 类；`idle` 评分同时把失败计入，两种保护叠加。

`idle` 的两个比例都需要至少两次成功检查。只有一次时，`FLOOR` 就是那一次延时本身，`PRES` 与 `BAD` 都是 0，所有节点会并列在最小的分数上，组只能从它们当中随机挑。这一轮里 `idle` 退回按延时排序，取延时的一半，与 `quick` 读同一个窗口的顺序一致：一次低延时的检查不该让一个节点看起来是最稳的那个。等第二次成功检查到来，分数就回到上面的比例制。

如果所有检查都失败，成功延时未知，两个目标的分数都记为 `TIMEOUT`；如果尚无检查结果，则没有可用分数。

分数来自有限次检查，不是节点或线路永远不变的“真实值”。比较分数时，也要考虑测量误差。

### 噪声：分数的不确定性

分数是根据有限次检查算出的估计值。换一批检查，分数和节点之间的差距都可能变化。这里的 `n` 是成功检查数；失败比例则以 `ALL` 为分母。

#### 单个节点的噪声估计

标准误差表示重新检查一批后，估计分数通常会变化多少。样本均值的标准误差可用样本标准差除以 `√n` 估算；中位数和以估计中心为基准的统计量，还会受数据分布影响。实现采用以下近似值：

```
SE_proxy(score) ≈ √( (1.2533·sd(x)/√n)² + (1.858·sd(d)/√n)² )                     # quick
SE_proxy(score) ≈ 1000 · √( (1.2533·JIT/(FLOOR·√n))² + 0.5²·BAD(1−BAD)/ALL )     # idle
```

`SE_proxy` 是实现使用的近似噪声值，不是有限样本下的精确标准误差。它只用于[迟滞](#保留已有连接迟滞)，判断当前节点是否明显落后。[容差带](#选择节点容差带)回答的是另一个问题：两个节点能不能分开。因此两处算法不同：`quick` 的带宽使用 `JIT`，`idle` 只使用 `PRES` 的误差，不把 `BAD` 的误差算进带宽。原因见 [`idle` 的余量为什么这么算](#idle-的余量为什么这么算)。

`quick` 的两项分别是 `MED` 与 `JIT` 的误差。`idle` 的两项来源不同：

- **第一项是 `PRES` 的误差。** `FLOOR` 是跨窗口保留的定值，不随本次窗口变动，所以相除之后，`PRES` 的误差就是 `MED` 的误差除以 `FLOOR`。`FLOOR` 取的是历史最快值，噪声是一个方向单一的偏移，不随抽样次数被平均，因此不进入标准误差，见[推导](#推导)。
- **第二项是 `BAD` 的误差。** `BAD` 是一个比例，也就是“`ALL` 次尝试里有多少次没达标”，它的标准误按二项分布估计，`√(BAD(1−BAD)/ALL)`。分母是**全部尝试**而不是成功次数，因为失败已经计入这一项。它与第一项来自同一批检查，严格说存在相关；当前按独立处理，是一个简化。

启动后的第一轮，`FLOOR` 就是本轮的最快值，也就是 `MIN`。`MIN` 是极值，噪声比 `MED` 更大，所以这一轮的余量会低估实际波动，节点切换也会稍微积极一些。从第二轮开始，`FLOOR` 由多轮数据汇总，这个影响就小到可以忽略；它只会让 `PRES` 一起放大，排序几乎不动，见[设计取舍](#设计取舍地板不成熟会不会影响排序)。

这些估计依赖检查结果近似独立、分布在窗口内大致稳定等条件；小样本或明显趋势下尤其可能失准，详细说明见[推导](#推导)。成功样本少于 2 个时，实现使用基础分数作为噪声估计，而不套用上述公式。

#### 两个节点分数差的噪声

如果两个节点的测量误差互相独立，差值的方差就是两者方差之和：

```
SD(score_node − score_best) ≈ √(SE_proxy_node² + SE_proxy_best²)
```

若两者受到共同探测目标或共享线路状况影响，误差可能相关，差值方差还应包含 `−2·Cov(score_node, score_best)`。当前公式把协方差视为零，是一个简化假设。独立时先平方相加再开方，得到差值的标准差；这不是把两个误差直接相加，也不表示噪声会被消除。推导见[推导](#推导)。

#### 为什么不能从分数里“减掉噪声”

噪声表示估计值会怎样波动，不是固定偏差，不能从分数中减去一个通用数值。不同指标的误差变化方式也不同：`MED` 和 `BAD` 的误差会随 `1/√n` 缩小；`FLOOR` 在本窗口内不变。选择时用**容差带**容纳不确定性，而不是从分数中扣除噪声。

### 选择节点：容差带

选择节点时，分数接近最佳值的候选都视为“差不多好”，避免因微小或不确定的差距频繁切换。`tolerance` 用来设置这个范围。两个目标衡量的内容不同，因此默认值也不同：

| 目标 | 分数 | 默认 |
| --- | --- | --- |
| `quick` | `MED + JIT` | `50ms` |
| `idle` | `1000 × (PRES + 0.5 × BAD)` | `50ms` |

两个目标的默认值相同，因为分数都以毫秒表示：`quick` 的 50ms 是绝对延时差，`idle` 的 50ms 相当于 1000ms 标尺上的 5% 相对退化。

选择范围还会加上**分辨余量**，避免把测量波动当成节点差异。两个目标的分数都以毫秒表示，因此使用相同形式的公式：

```
band = tolerance + 2√2 × 噪声_best / √n
cut  = score_best + band
```

`quick` 的噪声取 `JIT_best`；`idle` 的噪声取 `1000 × 1.2533·JIT/FLOOR`，只由 `PRES` 这一项得出——`BAD` 虽然进分数，但不进带宽。两者都除以成功检查数的平方根，也都以**典型偏差**（`JIT`）估 `σ`，不取离散度 `sd(x)`：余量的职责是把节点分开，一个被单次慢探测撑大的余量会把所有节点都吞进去。系数 2 是工程上的启发式取值，不是 95% 置信保证。详见下一节。

实现只在成功样本数 `n ≥ 2` 时加入噪声余量；`n < 2` 时 `band = tolerance`。

候选分数不高于 `cut` 时，仍会留在可选范围内。样本越多，余量中的 `1/√n` 项越小，因此 `band` 会逐渐接近配置值，但**不会小于 `tolerance`**。

#### `quick` 的余量为什么取 `JIT_best`

比较前不知道候选节点是谁、测量有多准，所以实现假设候选与最佳节点测得一样准；两边都用最佳节点的 `JIT` 作为噪声尺度。

```
margin = 2 × √( (JIT_best/√n)² + (JIT_best/√n)² )
       = 2√2 × JIT_best/√n
```

噪声尺度取 `JIT_best`：

- **不取 `DEV_best`**：`DEV` 是平均偏差，一次尖峰只按自己的份额计入，用它估余量会把“偶尔卡一次”的节点算得比实际更稳；而 `JIT` 取偏差的中位数，对少数异常值不敏感，更适合当噪声尺度。
- **不直接用完整的分数噪声估计**：它含有平方离差，一次慢探测就可能把估计撑大；余量随之变宽，会让明显更差的候选也进入范围。这是一项稳健的工程取舍，不是实际噪声的数学下界或 95% 分辨力保证。

#### `idle` 的余量为什么这么算

`idle` 的分数有两项，但只有深度那一项决定带宽的宽度。

**`PRES` 的误差。** `PRES` 等于 `MED` 除以 `FLOOR` 再减一，而 `FLOOR` 是跨窗口保留的定值，本次窗口的抽样不会改动它。除以一个常数不改变相对误差，所以：

```
SE(PRES) ≈ SE(MED) / FLOOR ≈ 1.2533 · σ / (FLOOR · √n)
```

要估的是 `σ`，即节点单次检查的波动。这里用 `JIT`，即偏差中位数换算出的稳健刻度，而不取 `sd(x)`：**余量的职责是分辨**，而 `sd(x)` 会被一次慢探测撑大，让余量宽到所有节点都算“差不多好”。

**`BAD` 不进入带宽。** 它照常进入分数，但带宽只由 `PRES` 的误差加上 `tolerance` 构成。这有两层理由。

第一层是带宽的用途。带宽要回答的是“这个节点有没有可能是和最好的一样好”，它存在的目的是不因为测量波动丢掉一个好节点。`PRES` 的偏差是随机抽样的噪声，方向对称，慢了一次不代表它慢，宽容它是对的。`BAD` 回答的不是快慢，是**会不会坏**，两个方向的代价并不对称：放过一个会停顿的节点，代价是真实的坏请求；误杀一个好节点，代价只是少一个候选，而候选还有三十个。所以对不确定的频率，应当要求证据，而不是放宽门槛。**不确定性不该让一个节点更容易被选中。**

第二层是这个比率在小样本上的行为。`BAD` 是一个比例，它的二项标准误是 `√(BAD(1−BAD)/ALL)`，在 `BAD` 为 0 时恰好等于 0。若把它加进带宽，带宽的宽度就取决于**最佳节点在这个窗口里有没有恰好踩到一次坏检查**，而不是取决于它有多准。

`BAD` 的误差并不消失，它仍然用在[迟滞](#保留已有连接迟滞)里：那里面对的是一个已知节点，目的是不被一次波动打断，需要知道的是“这个节点的分数可能差多少”，用途与带宽正相反。两处因此分别估计，不共用同一个量。

余量是**绝对**的：它不随分数大小变化。一个常驻排队 10% 的节点和一个几乎不排队的节点，用的余量相同。这也让共用的 `tolerance` 默认值 `50ms` 有意义：两个目标的分数都在几十到几百毫秒的量级，配置值和实际带宽处在同一尺度上。

样本越多，这个余量越小，这与 `quick` 一致。`FLOOR` 本身的不确定性小于 `MED` 的，因为它由多个窗口汇总而来。

### 保留已有连接：迟滞

开启打断链接配置后，节点被替换时，原有连接可以暂时保留。刚离开选择范围的节点，只要它超过选择带的部分仍在噪声余量内，就不会立即断开连接：

```
noise     = 2 × √(SE_proxy_node² + SE_proxy_best²)
allowance = band + min(band, noise)
```

这里比较的是当前使用的节点和最佳节点，因此分别使用各自的噪声估计。计算时假设两者误差独立；如果它们共用探测目标或线路，可能存在相关性，但公式没有计入。`min(band, noise)` 会把额外保留范围限制在一个 `band` 以内，因此节点最多可以保留到距最佳节点**两个带宽**的位置。迟滞用来应对测量波动，不是为了长期保留明显更差的节点。

`idle` 的 `SE_proxy` 用完整的离散度 `sd(x)` 估 `PRES` 的误差，而带宽按 `JIT` 算，两者可以差一个数量级，于是 `min(band, noise)` 落在 `band` 上，保留范围就是**两倍带宽**。这正是封顶的用途——两个数回答的是不同问题：带宽要多窄才能分辨节点，噪声估计是某个已知节点的分数可能差多少。

#### 为什么连接保留也使用噪声估计

连接保留和选择带都在处理“观测差异是否足够可信”，但回答的问题不同：选择带要对所有未知候选采用统一、稳健的余量；连接保留面对的是一个已知节点，因此可以使用该节点和最佳节点各自的噪声估计。这里的系数 2 同样是工程启发式，不代表严格的置信概率。

#### `quick` 与 `idle` 的表现

- `quick` 的噪声估计由延时样本的离散度和绝对偏差的离散度共同决定，样本越多越准。
- `idle` 的噪声估计由 `PRES`（随 `MED` 的误差）与 `BAD`（二项比例）两项合成；带宽只用前一项，这里两项都要，因为迟滞要的是这种节点可能差多少。第二项在 `BAD` 为 0 时趋于零，所以一个完全干净的节点，误差只由 `PRES` 决定。它的分数不因窗口换了就归零：一个节点开始拥堵后，只要 `FLOOR` 还是它空闲时的那个值，`PRES` 与 `BAD` 就会一起把它送出选择带，直到拥堵缓解、或者 `FLOOR` 因有效期到期而重新学起。

#### `urltest` 的单节点选择

`urltest` 一次只选择一个节点，没有负载均衡组的第二层连接保留。迟滞直接放在选择中：在用节点的分数不超过最佳节点的 `Limit(best)` 时继续使用，即最多容忍**一个带宽**的差距。

连接保留与节点选择是两项独立决策：前者决定要不要中断已有连接，后者决定新连接可以使用哪些节点。

### 设计取舍：为什么不按标准差排序

样本标准差是常用的离散度指标，但不适合直接作为这里的节点波动分数，主要有三点原因：

1. **它以平均值为中心，而平均值会被离群值拉偏。** 十次检查里九次在 450ms、一次 3.15s，均值就被从 450ms 拉到 720ms。
   其余九次检查的偏差因此从 0 变成了 270ms，尽管它们一个都没变。
2. **它会把偏差平方，所以一个样本就可能主导结果。** 平方让一次尖峰的权重按幅度的平方增长：同一个例子里，那一次检查贡献了九成的方差。
   最终得到的离散度描述的是这次探测，而不是节点的通常状态。
3. **开方后也不能还原到合适的尺度。** `n` 个样本中，一个幅度为 `X` 的尖峰对平均偏差的贡献是 `X/n`，
   正好对应它拖慢的连接占比；但它对标准差的贡献是 `X/√n`。当 `n = 10` 时，这已经高出 3.2 倍，而且窗口越长，差距越大。

`DEV` 仍然计算相对中位数的偏差，但采用线性平均，不让一个尖峰移动中心。在 200ms 与 800ms 之间来回的节点仍会有较大的 `DEV`；它不是忽略不稳定，而是避免让一个样本单独决定分数。它在当前设计里只用于报告，不参与排序。

`idle` 的两个比例也都是线性的或计数的，不含平方：

- `PRES` 是一个比值，不是平方；
- `BAD` 数的是次数占比，一个极端值只按一次计入。

它们量的不是“窗口内忽快忽慢多少”，而是“比它自己最好时差了多少、差了几次”。这两件事在窗口里可能出现同样的离散度，但后果不同：一个在 200ms 和 800ms 之间来回的节点，中位数约 500、地板仍是 200，`PRES` 约 1.5、`BAD` 约一半；一个稳定在 800ms 的节点，地板也是 800，两个比例都是零——它从未更快过，所以当前这个慢不是排队造成的。**`idle` 选后者。** 稳定的慢是一个可以用 `max_rtt` 处理的已知成本，忽快忽慢不是：同一段流量时快时慢，没法预先支取。

这不表示标准差完全不用：`quick` 仍用样本标准差估计分数噪声；这里的取舍是**不把它直接当作节点排序分数**。

### 设计取舍：为什么趋势不直接进入分数

窗口里的样本有先后顺序，但上面这些统计量都不看顺序：无论怎样打乱样本，`MED`、`PRES`、`BAD`、`JIT` 和 `DEV` 都不会变。
所以，一个持续变差十分钟的节点，只要延时分布相同，读数就会和一直处于该状态的节点一样。

`PRES` 与 `BAD` 部分补偿了这一点，但方式和趋势不同：它们比较的不是窗口内的先后顺序，而是**当前与历史最好**。一个从 200ms 变到 600ms 的节点，`MED` 立刻变成 600，`FLOOR` 还是 200，`PRES` 立刻变成 2.0，不需要等趋势累积；一个从 600ms 变到 200ms 的节点，`FLOOR` 跟着降到 200，`PRES` 立刻回到接近零，也不会被过去的坏状态连累。**方向因此不需要额外处理：`FLOOR` 只向下移动，改进会立刻被认可，恶化会立刻兑现。**

比较前后半窗（`median(后半) − median(前半)`）确实能补充信息，而且计算成本很低：它可以分辨“刚开始变差”和“已经差了一阵子”。但趋势没有纳入分数，因为这样一来，`interval` 改变时排名也会改变。排名应该反映节点本身，而不该取决于检查的频率。趋势属于决策，和容差类似，不属于测量结果。

它也需要小心：`sampling` 为 10 时，后半窗五个样本里连续两次异常并不能推动它的中位数，因此趋势要到第三次才会出现。
这使它成为一个比“最近一次检查”更慢的信号，而后者本来就在统计量里。

窗口长度也有类似的取舍：在延时分布相对稳定时，窗口越长，估计通常越平滑、噪声越小；但旧样本占比也越大，节点发生变化后分数跟上的速度越慢。缩短窗口会更快反映变化，但估计也更容易受偶然波动影响。因此，降低噪声和跟上变化是同一个采样窗口选择的两端。

### 设计取舍：基线为什么排成一圈格子

基线记录“这个节点最好的状态”，于是同时受两个相反的约束：**它必须记得足够久**，因为空载只在日低谷出现，看得太短就会把拥堵时的水平当成空载水平；**它又必须忘掉**，因为同名节点可能换了线路、换了机器，旧基线立刻是错的。

单独设置“何时过期”的计时器，很难同时满足这两个要求，因为过期是一次性事件：到期前什么都不变，到期后记录又会一下子全丢。改用**一圈格子**后，记忆和遗忘都可以逐步进行：

```
48 格 × 30 分钟 = 24 小时
每 30 分钟只有一格被重置，其余 47 格照旧
```

- **记得够久**：环覆盖 24 小时，每个时段都有自己的记录，因此基线始终有完整一天的观测作参考。
- **忘得平滑**：没有“过期”这个动作，只有一格被下一次同格记录覆盖。基线不会在某一个瞬间整体作废，也不会因为一次重置让全组的分数同时归零。

格子按墙钟时间划分，而不是按运行时长划分，所以第 40 格始终对应 20:00–20:30。这样记录更有针对性：每格记住的是**节点在这个时段最快能有多快**，而不是任意 24 小时内的最低值。

格子数量决定了记录的时间粒度，也影响每格有多少观测：格子越少，每格覆盖的时间越长，一个时段内的变化都会压成一个最小值；格子越多，每格里的探测越少，记录可能只由一两次探测决定。48 格可以整除一天，也能让每格容纳若干轮检查。和 `sampling`、`interval` 一样，它是**实现中的常量，不是配置项**；修改时必须同时考虑探测频率，不适合单独交给用户配置。

**代价。** 地板是每格最小值的再取最小，仍然是“最小值”，所以它偏向记录最乐观的一次。这与它的用途一致（要的是空载水平），但意味着偶尔一次走运的探测会略微压低地板，让每个节点的 `PRES` 都偏大一点，见[推导](#推导)里对估计方式的比较。这个偏差是**共同**的，不改变排序，只影响 `tolerance` 的相对严格程度。

#### 更新、过期与启动

**更新。** 每轮先更新格子，再计算分数，因此本轮观测会立即生效：

```
slot[k]  = min(slot[k], MIN)               # 进新格时先重置为 MIN，再取格内最小值
FLOOR    = min(最近 24 小时内各格的值)
PRES     = max(0, MED − FLOOR) / FLOOR
BAD      = (#{xᵢ > 2 × FLOOR} + FAIL) / ALL
```

先更新格子不会让分数归零：每格存的是最小值，所以更新后 `FLOOR ≤ MIN ≤ MED`，`PRES` 仍是非负的比值，`BAD` 仍是一个占比。如果先算分再更新，节点变快后要等到下一轮才会反映出来，并没有好处。

成功检查少于两次时，不更新格子：唯一的一次结果可能只是运气，也可能是探测尚未稳定，不该用它来决定之后一天的地板。这一轮的 `PRES` 取该次延时的一半，详见[统计量](#统计量从成功检查中计算)。

**过期。** 没有单独的过期步骤：24 小时后，同一格会被下一轮记录覆盖，旧记录随之失效。因此，基线始终来自**实际观测过的时段**。这避免了像“到期时重置为当前值”那样，把眼下的拥堵误当成最快水平。如果某个时段一直拥堵，该时段的记录会逐渐变高，但其他时段的记录仍然有效。只有长期都处于拥堵状态时，整体基线才会升高，相当于承认“这个节点平时就是这么慢”。

**跳变。** 节点状态平稳或缓慢变化时，基线每次只会移动一格带来的变化量，因为每 30 分钟只有一格会被替换。以每天变慢 144ms 的节点为例：一次性过期会造成 144ms 的突变；使用格子后，这个变化会分散到一天内的 48 次更新中，每次约 11ms。**不过，突发变化（例如更换线路或机器）仍会造成一次跳变**：最后一格旧数据被覆盖时，最小值必须变成下一个最小值，变化幅度就是状态变化本身。这是遗忘旧数据必然付出的代价，不是能靠平滑消除的噪声。

**启动。** 第一轮写入的就是本轮最快值，因此 `FLOOR` 从一开始就是 `MIN`，不需要单独的降级处理。之后地板会从一格开始逐步填满，完整覆盖一天需要 24 小时。重启后也是如此：地板保存在内存中，重启后需要重新积累。恢复期间，每格覆盖的时段较少，地板更容易偏高；这是遗忘旧数据的代价，但排序仍然成立，理由见[地板不成熟会不会影响排序](#设计取舍地板不成熟会不会影响排序)。

### 设计取舍：为什么阈值是两倍，权重是 0.5

`BAD` 的判据是“慢到自己最好水平的两倍”，权重 `0.5` 让一个“每次都翻倍”的节点在标尺上加 500。两个数字都不是从数据里拟合出来的，而是各自有一条简单的依据。

**为什么是两倍。** 两倍是“耗时翻了一番”的界，也是最常用来判定一条线路开始排队的门槛。两头各有失效的方式：

- **定得低（比如 1.5 倍）**，正常的抖动和探测波动也会越过它，于是每个节点都带着一截 `BAD`，节点之间失去分辨力——这一项本来要区分的是“偶尔排队”和“一直排队”，门槛一低就分不出来了。
- **定得高（比如 3 倍）**，只有持续的长队列才够得上，几乎所有节点都归零，这一项等于不存在，分数退回只按深度排。

两倍落在这两端之间：正常的波动够不到，真正的排队一定越得过去。

**为什么是 0.5。** 它把“频率”换算到和“深度”同一把尺子上：`PRES` 的量级落在 0 到 1 之间，而一个“每次检查都翻倍”的节点应该被判得和最坏的常驻排队一样差，也就是加一个接近 1 的量。取 0.5 意味着“每次翻倍”比“常驻排队 50%”略重一点，这个量级关系是判断，不是拟合。

它不是随手可取的值，但也不是需要精细调校的值——它定的是**换算率**：几次坏检查等于一个百分点排队。换算率一变，边界上的节点就换人：宽一点，多收一两个只是略差的节点；窄一点，只留下最干净的。所以这是一个策略问题——你希望“偶尔卡一下”在多大程度上等价于“一直慢一点”。明显不同的节点之间的先后不取决于这个数，只有处在带宽边缘的那几个会。

这两项**必须分开**，不能合成一个，因为它们抓的是不同的缺陷：

| 节点 | `PRES` | `BAD` | 只按深度排 | 只按频率排 |
| --- | --- | --- | --- | --- |
| 快但常掉线 | 很低 | 很高 | 第一 | 中游 |
| 慢但很稳 | 中等 | 很低 | 中游 | 第一 |
| 又慢又常掉线 | 很高 | 很高 | 垫底 | 垫底 |

只用其中一个，都会把另一类明显的缺陷放过。

### 设计取舍：为什么两个分项都是比值

`idle` 要回答“这个节点比它自己做得到的差多少”，而“差多少”有两种写法：差值（`MED − FLOOR`）和比值（`(MED − FLOOR) / FLOOR`）。选比值不是偏好，是唯一能去掉距离的写法。

**差值会把距离重新带回来。** 一个 400ms 的节点地板是 380，多等了 20ms；一个 900ms 的节点地板是 860，多等了 40ms。按差值，后者更差；但那 40ms 里有一部分是它天生更远：同样的排队程度，线路越长，多出来的毫秒数就越大。差值分不开“我在排队”和“我天生远”，因为它本身就带着地板的量纲。

**比值把地板约掉了。** `PRES` 是“多等的部分占它自己地板的比例”，同样的排队程度在远节点和近节点上是同一个数；`BAD` 只与地板比较，同样不带距离。两项都是无量纲的，这才叫“与距离无关”。

**代价要认。** 比值会放大低地板节点的相对退化：一个 176ms、地板 149ms、偶尔翻倍的节点，`PRES` 是 0.18，看起来比一个 525ms、`PRES` 0.03 的节点差得多。按绝对延时它确实快，但按“有没有在超负荷运转”它确实更差。`idle` 选后者是设计意图，不是副作用；如果希望绝对延时不被牺牲，那是 `max_rtt` 和 `quick` 的职责。想两者兼顾，可以让不同延时档各自出名額，但那已经不是 `idle` 本身。

### 设计取舍：地板不成熟会不会影响排序

`FLOOR` 要累积满 24 小时才有全部时段的数据，刚启动时它只是当前窗口的最快一次。这会不会让排序失效？

**不会，因为 `FLOOR` 在分数里是分母。** 一个节点的地板错多少，它的 `PRES` 就等比例缩放多少，`BAD` 也按同一个地板重算，两项一起变。这与差值形式有本质区别：差值里地板错 10ms 就是平移 10ms，直接改变名次；比值里地板按比例缩放，名次按同一尺度伸缩，排序基本不动。

只有当**不同节点**的地板错得不成比例时，排序才会动。而地板偏差有两个来源，都不按节点胡来：一是取最小值带来的系统性偏低，所有节点朝同一个方向偏；二是每个节点的地板落到哪一个采样值上，这取决于它自己的分布宽度，分布窄的节点很快收敛到真实下限。所以地板不成熟的时候，分数整体偏乐观一点，`tolerance` 的相对严格程度跟着变一点，名次不变。

**代价也有边界。** 地板误差越大，比值形式越吃亏：分母被噪声放大到一定程度，它就和差值形式打平。所以这条设计依赖一个前提：地板不能**按节点错得离谱**。换机器、换线路会让旧地板彻底失效，这正是 48 格环 24 小时过期要处理的情况。

还有一处耦合值得记下：波动越大的节点，地板被压得越低，`PRES` 就被抬高。因为波动大本身就是缺陷，这个方向和设计意图一致，但它意味着 `PRES` 里混入了一部分波动信息，与 `BAD` 有重叠；重叠的方向是一致的，不会让一个安静的节点因为“看起来波动大”而占便宜。

### 推导

本节解释噪声估计中用到的公式、常数和假设。先约定记号：

- `n` 是成功检查的数量；`xᵢ` 是第 `i` 次成功检查的延时；`MED` 是这些延时的样本中位数。
- `sd(…)` 是样本标准差，用来估计一批数据通常离开其中心多远。
- `Var(…)` 是方差，即波动大小的平方；`SE`（标准误差）表示一个估计值在重复采样时通常会波动多少，等于方差开平方。
- `SE_proxy` 表示实现使用的噪声估计。它是近似值，不是精确标准误差或置信区间。

下面的推导会假设检查结果彼此独立，并来自一个采样窗口内稳定的分布。分析 `JIT` 时还会用到分布对称的假设；真实网络不一定完全满足这些条件。

#### `idle`：两个比例的误差估计

`idle` 按 `score = 1000 × (PRES + 0.5 × BAD)` 排序。要估计的是：重新做一批检查时，这个和通常会变多少。

**第一步：`FLOOR` 在一轮之内是常数。** `FLOOR` 由各格的最小值汇总而来，本轮写入之后它就是一个定值。减它是减常数，除以它也是除以常数，所以两个比例各自只随窗口内的量变化：

```
Var(PRES) = Var(MED / FLOOR) = Var(MED) / FLOOR²
```

本轮写入可以让 `FLOOR` **下移**（当这一轮出现了更快的一次），此时 `PRES` 的实际参照是本轮的 `MIN`，还多带一点 `MIN` 的噪声。这是一个只在刷新记录时发生的、方向单一的事件，而不是每轮都有的抖动，所以噪声模型仍以 `MED` 为主。

`FLOOR` 本身的偏差是另一回事，它是**系统性的**：最小值偏低，每个节点的 `PRES` 都按同一方向偏大，而这段偏差不会随抽样次数被平均掉，因此不进入标准误差，只能靠理解它的方向来对待，见第五步。

**第二步：`MED` 的方差。** 中位数只看样本的排序位置，因此它的方差取决于中位数附近的概率密度 `f(m)`：

```
Var(MED) ≈ 1 / (4n·f(m)²)
```

正态近似下 `f(m) = 1/(σ√(2π))`，代入得 `(π/2)·σ²/n`，开方即：

```
SE(MED) ≈ 1.2533 · σ / √n
```

`σ` 是节点单次检查的波动。实现用两个方式估它：`sd(x)` 是样本标准差，是标准误差的原始定义所用的量；`JIT` 是偏差中位数乘 `1.4826`，是同一刻度的稳健估计，单次尖峰推不动它。两者分别用在两处：迟滞取前者，余量取后者，理由见 [`idle` 的余量为什么这么算](#idle-的余量为什么这么算)。`1.2533 = √(π/2)` 的来历见 [`quick`：`MED` 的误差](#quickmed-的误差)。

**第三步：合起来，得到 `PRES` 的误差。** 把第一步和第二步接上：

```
SE(PRES) ≈ SE(MED) / FLOOR ≈ 1.2533 · sd(x) / (FLOOR · √n)
```

余量里把 `sd(x)` 换成 `JIT`，形状不变。这是**绝对**误差，不随分数大小变化：一个常驻排队 10% 的节点和一个几乎不排队的节点，误差尺度相同——因为它们之间的差别只是 `MED` 不同，而误差只取决于 `σ`、`FLOOR` 与 `n`。

**第四步：`BAD` 的误差。** `BAD` 是 `ALL` 次尝试里没达标的次数除以 `ALL`，也就是一个二项比例。它的标准误为：

```
SE(BAD) ≈ √( BAD(1 − BAD) / ALL )
```

这一项的形状与第一项不同：它不依赖 `σ`，只依赖 `BAD` 本身与尝试次数。`BAD` 为 0 时它也是 0——正是这一点让它可以进入迟滞，却不能进入带宽，见 [`idle` 的余量为什么这么算](#idle-的余量为什么这么算)。

分母是全部尝试而不是成功次数：失败已经计入分子，用更小的分母会把误差算窄，而失败多的节点恰恰是误差该大的那个。

两项都在同一个窗口里算出，严格说相关；当前按方差相加把相关当作零：

```
SE_proxy(score) ≈ 1000 · √( SE(PRES)² + 0.5² · SE(BAD)² )
```

这是**迟滞**用的噪声估计。带宽只用第三步那一项，再用 `JIT` 替换 `sd(x)`：

```
带宽的余量 = 2√2 · 1000 · 1.2533 · JIT / (FLOOR · √n)
```

**第五步：`FLOOR` 取最小值，因此偏乐观。** `FLOOR` 要回答“这个节点最好能有多快”，实现直接取见过的最快一次延时，不做平滑。用一天 1440 次检查、真实空闲 200ms、`sd = 8` 的模拟：

| 估计方式 | 得到的 `FLOOR` | 空闲时读到的 `PRES` |
| --- | --- | --- |
| **最小的一次（实现）** | **175** | **14%** |
| 各窗口中位数的最小值 | 191 | 5% |
| 全天 10 分位 | 190 | 5% |
| 全天中位数 | 200 | 0% |

最小值系统地偏低约 3 个标准差：一天里有 1440 次机会，总有一次走运。代价是每个节点的 `PRES` 都大几个百分点，好处是这个量**不迟钝**。

按窗口的中位数记录会安静得多（偏差只有几个百分点），但它回答的是另一个问题：“这个节点**通常**有多快”。平稳时段里每个节点的中位数都等于它自己，`PRES` 于是全为零，`idle` 没有排序可言。更糟的是一类真实的节点：它的延时在两个带宽池之间轮换，两低两高时中位数正好落在两峰中间，一个它从未达到过的值，而这个中点逐轮稳定，于是它被读成最稳的一个（`MED = 919`、`MIN = 556`，按中位数记地板得 0，按最小值记得 65%）。取最小值就不会被这种结构骗过。

这个偏差是**共同**的，不改变排序：两个节点都偏乐观同样的比例，它们在 `PRES` 上的差仍然是它们真实差距的差。它只影响零点，也就是 `tolerance` 的相对严格程度。

#### `quick`：`MED` 的误差

`quick` 的分数是 `MED + JIT`。先看 `MED`：换一批检查结果，中位数也会变。它的误差取决于中位数附近有多“挤”：样本集中在中位数附近时，中位数通常不容易移动；附近样本稀疏时，少量样本变化就可能让它跳得更远。

用 `f(m)` 表示总体中位数 `m` 附近的概率密度。它可以理解为“延时落在中位数附近的密集程度”。样本较多时，中位数的方差近似为：

```
Var(MED) ≈ 1 / (4n·f(m)²)
```

对正态分布，`f(m) = 1/(σ√(2π))`。代入后可得：

```
Var(MED) ≈ (π/2)·σ²/n
SE(MED)  ≈ √(π/2)·σ/√n
          ≈ 1.2533·sd(x)/√n
```

这里用样本 `sd(x)` 估计总体标准差 `σ`。因此 `1.2533 = √(π/2)` 是**正态分布近似**下的系数：在该条件下，中位数的标准误差约比均值大 25%。延时分布明显偏斜或样本很少时，这个系数不一定合适。

#### `quick`：`JIT` 为什么乘 `1.4826`

`JIT` 用绝对偏差的中位数表示“典型波动”，再乘 `1.4826`，把它换到与标准差相同的刻度。这个常数从正态分布推来：

```
q = median(|X − m|)
P(|X − m| ≤ q) = 1/2
```

对称的正态分布中，“落在 `m` 左右 `q` 以内”占一半概率，所以从均值到 `m+q` 的概率是四分之一，即 `Φ(q/σ)=0.75`。因此：

```
q = Φ⁻¹(0.75)·σ ≈ 0.6745·σ
σ ≈ q / 0.6745 ≈ 1.4826·q
1.4826 = 1 / Φ⁻¹(0.75)
```

也就是说，对正态数据，偏差中位数约为 `0.6745σ`；乘上 `1.4826` 后，`JIT` 就能估计标准差的尺度。它是正态分布下的换算常数，不意味着实际延时一定服从正态分布。

#### `quick`：`JIT` 的误差估计

即使知道真实中心 `m`，`JIT` 也会因抽到哪一批样本而变化。设 `q` 是 `|X−m|` 的总体中位数，`g(q)` 是绝对偏差在 `q` 附近的概率密度。中心已知、分布对称且样本足够多时：

```
SE(median(|X − m|)) ≈ 1 / (2g(q)√n)
SE(JIT) ≈ 1.4826 / (2g(q)√n)
```

直观上，`q` 附近的绝对偏差越密集，中位数越不容易移动，误差就越小。若中心也要从同一批样本估计，或延时分布不对称，计算还需额外考虑这些影响。

当前实现使用 `1.858·sd(d)/√n` 作为这部分的工程噪声估计，其中 `1.858 = 1.4826 × 1.2533`。这个近似相当于把正态中位数的系数用于 `d`；但即使 `x` 服从正态分布，绝对偏差 `d` 也服从半正态分布，所以 `1.858` 不是严格推导出的标准误差系数。它应理解为实现采用的估计值，而不是精确的概率保证。

#### `quick`：合并 `MED` 与 `JIT` 的误差

若两个量的误差独立，它们之和的方差就是各自方差相加；一般情况下还要加上协方差项：

```
Var(MED + JIT) =
    Var(MED) + Var(JIT) + 2·Cov(MED, JIT)
```

`MED` 与 `JIT` 用同一批样本计算，原则上可能相关。对称 IID 分布下，它们渐近独立，因此实现近似忽略协方差；有限样本或其他分布下，这不一定成立。当前实现的合成噪声估计为：

```
SE_proxy(score) ≈ √( SE_proxy(MED)² + SE_proxy(JIT)² )
```

因此，`quick` 中的系数和方差合成依赖上述分布与样本假设；这个 `SE_proxy` 是工程估计，不是 95% 置信区间。

#### 两个节点比较时，差值有多不确定

这一部分问的是：如果重新进行健康检查，节点分数与最佳节点分数之差会浮动多少。先记两个分数为随机量：

```
S_node   = 节点分数的随机量
S_best   = 最优节点分数的随机量
D        = S_node − S_best
Var(D)   = Var(S_node) + Var(S_best)
           − 2·Cov(S_node, S_best)
```

两个节点的测量误差独立时，协方差为零。若它们共用探测目标或受到同一线路状况影响，协方差可能不为零；当前实现忽略这项。独立假设下，把前面两项的噪声估计代入并开平方：

```
Var(D) ≈ SE_proxy_node² + SE_proxy_best²
SD(D)  ≈ √(SE_proxy_node² + SE_proxy_best²)
```

`SD(D)` 表示分数差在重测时的波动；公式中的 `SE_proxy` 是实现采用的估计，不是精确值。

#### `SD` 与 `SE` 是什么关系

`SD`（标准差）描述一个随机量的波动；`SE`（标准误差）描述一个估计值在重复采样时的波动。分数是根据样本计算出的估计值，因此它的标准差也就是它的标准误差。此处用 `SE_proxy` 表示实现对这个误差的近似估计。

`score_node` 和 `score_best` 在当前窗口里是已经观测到的定值；把它们称为随机量，是在问“如果重测一遍，它们可能变动多少”。
