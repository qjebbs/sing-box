# 节点评分

## 公式

评分：

```sh
ALL         = 窗口里的检查总数
MED         = median(x₁ … xₙ)
dᵢ          = |xᵢ − MED|                     # 第 i 次检查到中位数的偏差
JIT         = 1.4826 × median(dᵢ)
DEV         = (1/n) × Σdᵢ
SLOT        = 一天切成 48 格，每格 30 分钟
SLOT[k]     = 第 k 格里见过的最快一次
FLOOR       = min(最近 24 小时里各格的值)       # 它最好能做到多快
fᵢ          = 1 失败 / 0 成功                 # 第 i 次检查的失败指示
wᵢ(τ)       = exp(−(t − tᵢ) / τ)             # 按年龄的权重
S(τ)        = Σ wᵢ(τ)·fᵢ                     # 加权失败次数
W(τ)        = Σ wᵢ(τ)                        # 加权检查次数
F(τ)        = S(τ) / W(τ)                    # 加权失败率，0…1
FAIL_NEAR   = S(τ_N)                         # 近因失败权重（绝对量），节点资格比的是它
FAILR_NEAR  = F(τ_N)                         # 近因失败率，窗口内，τ_N = 5 分钟
FAILR_LONG  = F(τ_L)                         # 长期失败率，跨窗口，τ_L = 45 分钟
FAILR       = max(FAILR_NEAR, FAILR_LONG)    # 失败率，两个视界取大的
PRES        = max(0, MED − FLOOR) / FLOOR
BAD         = min(1, #{xᵢ > 2 × FLOOR} / ALL + FAILR)
COST        = MED + JIT
FAIL_COST   = min(TIMEOUT, 3 × COST)

idle_score  = 1000 × (PRES + 0.5 × BAD)
quick_score = (1 - FAILR) × COST + FAILR × FAIL_COST
```

容差带（分数的噪声即读数误差，按评分最好的节点计算）：

```sh
n         = 成功检查次数
SCORE_NOISE ≈ JIT / √n                                         # quick
SCORE_NOISE ≈ 1000 × 1.2533 × JIT / (FLOOR × √n)               # idle
BAND        = tolerance + 2 × √(SCORE_NOISE² + SCORE_NOISE²)   # 候选未知，假设和最好一样准
            = tolerance + 2√2 × SCORE_NOISE                    # n < 2 时不加误差项
```

迟滞：

```sh
sd(x)       = √(Σ(xᵢ − mean(x))² / (n − 1))            # 样本标准差，估标准误差用
sd(d)       = √(Σ(dᵢ − mean(d))² / (n − 1))            # 偏差的标准差
SCORE_SE    = √( (1.2533 × sd(x)/√n)² + (1.858 × sd(d)/√n)² )                          # quick 的完整分数噪声
SCORE_SE    = 1000 × √( (1.2533 × sd(x)/(FLOOR × √n))² + 0.5² × BAD × (1 − BAD)/ALL )  # idle 的完整分数噪声
NOISE_DIFF  = 2 × √(SCORE_SE_node² + SCORE_SE_best²)   # 两个节点分数之差的误差（2 × SD(D)）
ALLOWANCE   = BAND + min(BAND, NOISE_DIFF)             # 迟滞允许的超出量，最多两个带宽
```

## 评分

需要评分的目标有两个：

- `quick` 比的是实际延时，570ms 的节点就是比 400ms 的慢。
- `idle`：比的是退化，一个平时 200ms、晚高峰 400ms 的节点，也许 400ms 仍比远距离的节点低，但它已经在用自己两倍的时间跑。因此 `idle` 分数本质上是比例，跟远近无关。

评分前提是至少两次成功检查。只有一次时，说不出波动和压力有多大，退化到延时相关。

`SLOT` 按墙上的钟切：`k` 是当天第几个 30 分钟。检查会写测试时所在格，格子内只保留最小值。过了 24 小时，同一格会被下一次记录盖掉，旧值自然失效。

**`MED`** 是延时水平。用中位数而不是平均值，一次特别慢的检查拉不动它。

**`JIT`** 是**通常波动多少**。少数尖峰推不动它。它用绝对偏差的中位数表示“典型波动”，再乘 `1.4826` 换到和标准差同一刻度：

```sh
Φ = 标准正态分布的累积分布函数
q = median(|X − m|)
P(|X − m| ≤ q) = 1/2
```

对称的正态分布里，“落在 `m` 左右 `q` 以内”占一半概率，所以从均值到 `m+q` 是四分之一，即 `Φ(q/σ) = 0.75`。于是：

```sh
q      = Φ⁻¹(0.75) · σ ≈ 0.6745 · σ
σ      ≈ q / 0.6745 ≈ 1.4826 · q
1.4826 = 1 / Φ⁻¹(0.75)
```

也就是说，正态数据下偏差中位数约为 `0.6745σ`，乘 `1.4826` 就回到标准差的尺度。它是正态分布下的换算常数，不代表实际延时一定服从正态分布。

**`DEV`** 是**整体波动多少**。每次检查都算一份，尖峰多了才累积起来。它出现在报告里帮忙看问题，不参与排序。

**`FLOOR`** 是**见过的最快一次**。

**`PRES`** 是排队**有多深**：比它自己最好时多等了百分之多少。除以它自己的地板，传播距离就抵掉了。

**`F(τ)` 是加权失败率**：每次失败按年龄算一份 `exp(−(t − tᵢ) / τ)`，刚发生的为 1，持续衰减到 0，累计后再除以权重总量。

**`FAILR_NEAR`** 是**近因失败率**，即 `F(τ_N)`，窗口里失败率按年龄 `τ_N` 衰减。

**`FAILR_LONG`** 是**长期失败率**，即 `F(τ_L)`，按年龄 `τ_L` 衰减。它和 `FAILR_NEAR` 是同一个 `F(τ)` 的两个视界：`FAILR_NEAR` 管最近几分钟，决定此刻能不能用；`FAILR_LONG` 管最近几十分钟，决定之后还值不值得用。

**`BAD`** 是排队**有多频繁**：超过自己地板两倍的检查占多少，再加上失败占多少。它只跟自己地板比，同样与远近无关；一次特别慢也只算一次。

---

加权失败率，为什么使用指数加权？

权重只看过了多久，而且前后两段能合并：`w(a + b) = w(a) · w(b)`，
即先过 `a` 分钟再过 `b` 分钟，应该和一次过 `a+b` 分钟一样。

> 这个性质还确保了加权失败率可以只缓存结果，不需要缓存所有历史记录。

连续又不恒为零的函数里只有指数满足这条，所以定 `w(t) = exp(−t/τ)`。
换成线性衰减、阶梯衰减或固定次数的滑动窗口，同一个 `τ` 在 `1m` 和 `5m` 下代表的时长就不一样了。

近因失败权重还与资格挂钩，门槛是固定的：`FAIL_NEAR < 1` 是节点合格的必要条件。
刚失败的一次权重为 1，节点立刻不合格；下一次检查成功时，它的权重如果已经降到低于 1，节点回到候选。

它不是简单地看最后一次检查：只有单次失败才会在下一轮回来，连续失败会累加。以 2 分钟间隔为例，2 连败在下一次成功时仍有 `0.670 + 0.449 = 1.119`，还要再等一轮；3 连败在最后一次失败后约 4 分钟、9 连败约 6 分钟才恢复到门槛以下。
它回答的是“现在还在失败吗”，比 `FAILR_LONG` 短一个数量级。第一次失败仍然立刻降级，峰值期的反应不变；低谷期的一次偶发失败只要不再出现，就会自己衰减掉。这里不需要识别高峰：失败是否持续，本身就是最好的信号。

长期失败率 `FAILR_LONG` 要回答的是另一件事：合格候选里，谁的失败倾向更高。
这些候选只有最近几分钟没有一次完整失败，但分数里的 `FAILR_NEAR` 这时可以不是零：刚恢复的节点仍带着剩余权重，分数会继续按它降级。
`FAILR_LONG` 的 `τ` 取值只能在两头取平衡——既要较快淡化已经结束的故障，也不能被一次偶发失败带偏。取 45 分钟：一个节点连续失败 54 分钟后恢复，一小时之后就不该再为这次故障扣分。
`W` 的初值取 10，相当于“十次干净检查”：冷启动是“没见过它失败”，不是“见过它失败”。要是从零开始，一次失败能把 `F(τ_L)` 顶到 `1.0`——进程刚起来、网络还没就绪时每个节点的第一次检查都会失败，那样每个节点都要背着接近满分的估计走一小时。先验值也按时间衰减，历史一长就可以忽略。开着缓存时，恢复的历史直接取代这个起点。
它分辨力远不如延时，主要用在延时接近时打破平局，区分“又快又常掉线”和“稍慢但稳定”，不会动摇“快的还是快”。

## 容差带

分数和最好的差不多，就当一样好，免得为一点测量波动来回切。这个“差不多”由两部分组成：

1. `tolerance`：用户愿意为换节点接受的差距。
2. 分数的测量误差：分数来自有限次检查，换一批检查就会飘——这是分数的估计误差，不是单次检查的抖动。

要测量单次检查的噪声，唯一的办法是把同一次检查在平行宇宙里重做很多遍。
因为检测结果等于真实延时加上一次随机噪声，取得多次结果后，就能用总体方差估计出噪声的尺度 `σ`。

```sh
X         = μ + ε                        # 一次检查的延时
μ         = 这一刻的真实延时
ε         = 这一次的随机噪声
Xᵢ        = 在第 i 个宇宙里的取值，各宇宙随机
σ²        = Var(X) = Var(ε)              # 想象中的单次检查总体方差
```

我们操作不了平行宇宙，无法把一次检查重做多次。只能用同一时间窗口里的多次检查的分散程度 `sd(x)²` 去估它——前提是窗口内波动尺度不变，多次检查才算是同一个 `σ` 的样本。

```sh
xⱼ        = 现实窗口内第 j 次检查的观测值
mean      = (1/n) · Σxⱼ                     # 样本均值
sd(x)²    = (1/(n−1)) · Σ(xⱼ − mean)² ≈ σ²  # 用样本方差估 σ²
```

为了推导平均值的误差，想象把整个窗口的 `n` 次检查一起在平行宇宙里重做，`i` 是宇宙编号。
`Xᵢⱼ` 是第 `i` 个宇宙里第 `j` 次检查的延时；对 `j` 求和，就是第 `i` 个宇宙的 `sumᵢ`。
每个宇宙的 `sumᵢ` 都不同，各宇宙之间的差别就是这 `n` 次噪声合起来的效果。
例如三次检查，宇宙 A 得到 500 + 520 + 510 = 1530，宇宙 B 得到 480 + 540 + 500 = 1520；
`Var(sumᵢ)` 量的就是这种跨宇宙的分散。
每次检查独立，方差直接相加，所以是 `nσ²`。
我们这个世界实际测到的 `x₁ + … + xₙ` 只是其中一个宇宙的值，是定数，没有方差。

大写 `X` 是“可能测到的值”，小写 `x` 是“已经测到的值”：`Xⱼ` 是第 `j` 次检查的随机延时，
`Xᵢⱼ` 是它在第 `i` 个宇宙里的取值，`xⱼ` 是它在这一轮（我们这个宇宙）实际落下的数。
`Var(sumᵢ)`、`Var(meanᵢ)` 要跨宇宙求波动，所以用随机变量那一版；
`sd(x)²` 里的 `xⱼ` 是已经测到的数，算的是手里这批观测的分散。
`mean = (1/n) · Σxⱼ` 是已经算出的样本均值；把它看成“每个宇宙各算一个”的随机量时，就是 `Var(meanᵢ)` 讨论的对象。

```sh
sumᵢ       = Xᵢ₁ + … + Xᵢₙ                 # 第 i 个宇宙里的总和
Var(Xⱼ)    = σ²                            # 每次检查来自同一个分布
Var(sumᵢ)  = Var(X₁ + … + Xₙ)
           = Σ Var(Xⱼ) + 2·Σ Cov(Xⱼ, Xₖ)   # j < k
           = nσ² + 0                       # 独立 ⇒ 两两协方差为 0
           = nσ²
meanᵢ      = sumᵢ / n
Var(meanᵢ) = Var(sumᵢ / n)
           = (1/n²) · Var(sumᵢ)            # Var(aX) = a²·Var(X)
           = (1/n²) · nσ²
           = σ²/n
SE(mean)   = √Var(meanᵢ) = √(σ²/n) = σ/√n
```

中位数只看排名，不看具体数值，所以比均值“笨”一点。直观地看：重抽一批时，中位数落在哪里，
取决于有多少个样本落在真中位数 `m` 下面——这个数服从 `Binomial(n, 1/2)`，波动约 `√n/2` 个样本；
而中位数附近相邻样本的间距约 `1/(n·f(m))`，`f(m)` 是 `m` 附近的概率密度。
两者相乘，就是中位数的波动：

```sh
# 落在 m 下面的样本数 ~ Binomial(n, 1/2)，标准差 √n/2
# 中位数附近相邻样本的间距 ≈ 1/(n·f(m))
SE(MED)  ≈ (√n/2) × 1/(n·f(m)) = 1/(2·f(m)·√n)
Var(MED) ≈ 1/(4n·f(m)²)

# 正态下 f(m) = 1/(σ√(2π))
SE(MED)  ≈ σ√(2π)/(2√n) = √(π/2)·σ/√n = 1.2533·σ/√n
Var(MED) ≈ (π/2)·σ²/n
```

`π/2` 就是这份效率损失：中位数的方差是均值的 `π/2 ≈ 1.57` 倍，相同精度要多 `π/2` 倍的样本；`SE` 则多 `1.2533` 倍。

带宽只用分数的延迟部分：`quick` 用 `MED`，`idle` 用 `PRES = MED/FLOOR`。
先把 `σ` 换成用样本估的 `sd(x)`，得到严格形式：

```sh
quick: 1.2533 × sd(x)/√n
idle:  1000 × 1.2533 × sd(x)/(FLOOR × √n)
```

最后一步是带宽的简化：`sd(x)` 换成 `JIT`，`quick` 再把 `1.2533` 省掉：带宽要的是能分辨节点的窄尺度，不是精确的标准误差。

```sh
quick: SCORE_NOISE ≈ JIT/√n
idle:  SCORE_NOISE ≈ 1000 × 1.2533 × JIT/(FLOOR × √n)
```

样本越多，`1/√n` 越小，`band` 越接近 `tolerance`，但不会小于它；成功次数不到两次时不加误差项。分数不高于 `cut` 的都留在候选里。

----

`BAD` 进分数，但不进带宽。两层理由：

第一层是带宽要干什么。它问的是“这个节点有没有可能是和最好的一样好”，目的是别因为测量波动丢掉一个好节点。`PRES` 的偏差是抽样的噪声，方向对称，慢了一次不代表它慢，宽容它是对的。`BAD` 问的不是快慢，是**会不会坏**，两头代价不一样：放过一个会失败的节点，代价是真实的坏请求；误杀一个好节点，代价只是少一个候选，而候选还有三十个。

第二层是小样本上的行为。`BAD` 是比例，二项标准误差 `√(BAD(1−BAD)/ALL)` 在 `BAD` 为 0 时正好等于 0（失败部分按近因加权也一样）。要是把它加进带宽，带宽的宽度就取决于最好那个节点这一轮有没有恰好踩到一次坏检查，而不是取决于测得准不准——这显然不对。

`BAD` 的误差并没有丢，它还是用在迟滞里：那里面对的是一个已知节点，要的是别被一次波动打断，问的是“它可能差多少”，正好相反。两处各算各的，不共用。

带宽比的是两个分数——候选和最好，所以误差也得按两个估计来算。两边各有一份 `SCORE_NOISE`，彼此独立，差值的不确定性是 `√2 × SCORE_NOISE`；再留两个标准误差，余量就是 `2√2 × SCORE_NOISE`。这里还有简化：带宽并不知道实际会拿哪个节点来比，只能假设被比较节点和最佳节点一样准，所以两项相同，是两节点差值公式的一个特例。

## 保留已有连接：迟滞

负载均衡在开启打断已有连接的选项后，即使节点被换掉，只要超出的部分还在误差余量内，就不急着断。
因为负载均衡语义上就允许同时存在不同线路的连接，没有坏到一定程度无需打断连接，以免节点频繁进出选择线时，经常打断链接。
`urltest` 一次只允许一个节点，就没有这个逻辑。

带宽那节只用延迟项的读数噪声 `SCORE_NOISE`，并假设比较的两边一样准。迟滞面对的是一个已知节点，要的是同一件事的完整版：把分数里其余分项也算进来，而且两边各算各的，这个完整的分数噪声记作 `SCORE_SE`。
下面只补这两处新增的推导；`√n`、`1.2533`、`sd(x)` 与 `JIT` 的取舍已经在带宽那节讲过。
下面 `n` 是成功检查次数，`ALL` 是尝试次数；`SCORE_SE` 就是分数的标准误差，也就是换一批检查，分数会飘多少。

`quick` 的分数是 `MED + JIT`。`MED` 的误差已经有了，新增的是 `JIT`。`JIT` 本身是个中位数，所以误差可以直接套 `MED` 那条链，只是对象换成偏差 `d`：

```sh
dᵢ             = |xᵢ − MED|                    # 每次检查到 MED 的偏差
sd(d)          = √( Σ(dᵢ − mean(d))² / (n−1) ) # 偏差的样本标准差
JIT            = 1.4826 × median(dᵢ)
SE(median(dᵢ)) = 1.2533 × sd(d)/√n             # MED 那条链，对象换成 d
SE(JIT)        = 1.4826 × SE(median(dᵢ))
               = 1.4826 × 1.2533 × sd(d)/√n
               = 1.858 × sd(d)/√n
```

直观上，`d` 越集中，`JIT` 越稳。严格说，`d` 是围绕估出来的 `MED` 算的，中心本身也有误差；
这里按中心已知处理，是近似。
`1.858` 也是估计值，不是精确的概率保证：即使 `x` 服从正态，绝对偏差 `d` 也是半正态分布，
所以这个系数不是严格推出来的标准误差系数。

`idle` 的分数是 `1000 × (PRES + 0.5 × BAD)`。`PRES` 的误差不用重推，`BAD` 按比例估：

```
PRES     = MED / FLOOR                     # FLOOR 一轮内是定值
SE(PRES) = SE(MED) / FLOOR
SE(BAD)  = √( BAD × (1 − BAD) / ALL )      # 比例的二项标准误
```

`SE(BAD)` 不依赖 `σ`，只看 `BAD` 和尝试次数；`BAD` 为 0 时它也是 0。它的分母用全部尝试而不是成功次数：失败已经算在分子里，分母再缩小会把误差算窄。失败部分按年龄加权，有效样本是 `(Σw)² / Σw²`，小于 `ALL`，这里按 `ALL` 估，是近似。

`FLOOR` 的偏差是系统性的（最小值偏低，所有节点同向），不进标准误差。`PRES` 的误差是绝对的：常驻排队 10% 和几乎不排队的节点，误差尺度一样，只取决于 `σ`、`FLOOR` 和 `n`。一轮刷新记录时 `FLOOR` 可能下移，`PRES` 会多带一点新最小值的噪声；这只在刷新时发生，方向单一，误差模型仍以 `MED` 为主。

分数误差按分项方差相加：

```sh
SCORE_SE_quick = √( SE(MED)² + SE(JIT)² )                  # 协方差按 0
SCORE_SE_idle  = 1000 × √( SE(PRES)² + 0.5² × SE(BAD)² )   # 0.5 平方，1000 开方后提出
```

`quick` 两项同批样本，`idle` 两项同窗口，协方差严格说都可能不为零，这里按 0 处理。

迟滞比较两个节点，差值 `D = S_node − S_best`。这里的两个 `S` 是“重测一遍可能得到什么”的随机量，不是当下这两个定值。带宽那节假设两边一样准，于是化成 `√2 × SCORE_NOISE`；这里两边各用自己的 `SCORE_SE`。共用探测目标或同一段线路时协方差可能不为零，同样按 0 处理：

```sh
SD(D)      = √(SCORE_SE_node² + SCORE_SE_best²)
NOISE_DIFF = 2 × SD(D)     # 2 是带宽那节的两个标准误差
```

所以 `NOISE_DIFF` 记的是差值的误差**幅度**，不是差值的标准误差：后者是 `SD(D)`，`NOISE_DIFF` 是它的两倍。

于是，保留范围：

```sh
ALLOWANCE = BAND + min(BAND, NOISE_DIFF)
```

多出来的 `NOISE_DIFF` 再封顶一个 `BAND`：`idle` 的 `SCORE_SE` 往往比带宽的误差项大，不封顶会把保留范围撑得很宽；
封顶后最多留到离最好**两个带宽**的位置。迟滞是为了扛住测量波动，不是长期留着明显更差的节点。

只有状态相同的节点才按分数比较；已经掉到更差类别的不保留。
成功次数不到两次的节点没有可估的误差，代码把它的 `SCORE_SE` 取成整个分数，这时 `NOISE_DIFF` 通常会撞到 `BAND` 上限。

## 设计取舍

### 为什么不按标准差排序

样本标准差是常见的离散度指标，但不适合直接拿来当节点的波动分数，主要原因有三个：

1. **它以平均值为中心，而平均值会被离群值带偏。** 十次检查九次在 450ms、一次 3.15s，均值就从 450ms 被拉到 720ms，剩下九次的偏差凭空从 0 变成 270ms——尽管它们一次都没变。
2. **它把偏差平方，所以一个样本就能当家。** 同一个例子里，那一次检查贡献了九成方差，算出来描述的是这次探测，不是节点平时的样子。
3. **开方之后也回不到合适的尺度。** `n` 个样本里一个幅度 `X` 的尖峰，对平均偏差的贡献是 `X/n`，正好对上它拖慢的连接占比；对标准差的贡献却是 `X/√n`，`n = 10` 时就高出三倍多，窗口越长差得越多。

`DEV` 仍然算与中位数的偏差，但用线性平均，不让一个尖峰挪动中心。在 200ms 和 800ms 之间来回的节点照样有大的 `DEV`，它不是忽略不稳定，而是不让一个样本单独说了算。目前它只用于报告，不参与排序。

`idle` 的两个比例也都不含平方：`PRES` 是比值，`BAD` 的慢检查部分数次数，失败部分按年龄加权（权重不超过 1），一个极端值只算一次。它们量的不是“窗口里忽快忽慢多少”，而是“比自己最好差了多少、差了几次、最近一次有多近”。这两件事在窗口里可能有同样的离散度，后果却不同：一个在 200ms 和 800ms 之间来回的节点，中位数约 500、地板还是 200，`PRES` 约 1.5、`BAD` 约一半；一个稳定在 800ms 的节点，地板也是 800，两个比例都是零——它从没更快过，所以现在这个慢不是排队。**`idle` 选后者。** 稳定的慢是可以用 `max_rtt` 处理的已知成本，忽快忽慢不是：同一段流量时快时慢，没法预先安排。

标准差并没有被完全排除：`quick` 还用样本标准差估分数误差，只是不把它直接当排序分数。

### 为什么趋势不直接进入分数

窗口里的样本有先后顺序，`MED`、`PRES`、`JIT`、`DEV` 都不看顺序：怎么打乱都不变。所以一个持续变差十分钟的节点，只要延时分布相同，这几个统计量的读数和一直就这个样子的节点一模一样。`BAD` 的慢检查部分也不看顺序，但失败部分按年龄加权，所以 `BAD` 会区分“最近刚失败”和“很久以前失败”——这正是近因失败率存在的理由。

`PRES` 和 `BAD` 补了一部分，但方式不同：`PRES` 比的不是窗口里的先后，而是**现在和历史最好**；`BAD` 的失败部分还额外看年龄。从 200ms 变到 600ms 的节点，`MED` 立刻是 600，`FLOOR` 还是 200，`PRES` 立刻变 2.0，不用等趋势攒出来；从 600ms 变回 200ms 的节点，`FLOOR` 跟着降到 200，`PRES` 马上回到接近零，也不会被过去的坏状态拖着。**方向因此不用单独处理：`FLOOR` 只会往下走，变好立刻认，变差立刻兑现。**

比较前后半窗（`median(后半) − median(前半)`）确实能多看出点东西，算起来也很便宜，能分辨“刚开始变差”和“已经差了一阵子”。但趋势没进分数，是因为一进来，`interval` 一变排名就会变。排名该反映节点本身，不该取决于多久查一次。趋势属于决策，和容差是一类东西，不属于测量结果。

它还得小心用：`sampling` 是 10 时，后半窗五个样本里连着两次异常推不动中位数，要到第三次才看得见。这样它比“最近一次检查”还慢，而后者本来就在统计量里。

窗口长度也是同一笔账：延时分布大体稳定时，窗口越长越平滑、噪声越小；可旧样本占的比重也越大，节点变了分数跟得越慢。缩短窗口跟得更紧，也更容易被偶然波动带着走。降低噪声和跟上变化，是同一个窗口选择的两头。

### 基线为什么排成一圈格子

基线记的是“这个节点最好的样子”，它同时被两个相反的要求夹着：**要记得够久**，因为空载只出现在日低谷，看得太短就把拥堵时的水平当成空载；**又要忘得掉**，因为同名节点可能换了线路、换了机器，旧基线立刻就是错的。

单独设一个“什么时候过期”的计时器很难两头兼顾，因为过期是一次性事件：到期前什么都不变，到期那一刻全变。切成格子就没这个问题：

```sh
48 格 × 30 分钟 = 24 小时
每 30 分钟只有一格被重置，其余 47 格照旧
```

- **记得够久**：一圈盖住 24 小时，每个时段都有自己的记录，基线随时有完整一天作参考。
- **忘得平顺**：没有“过期”这个动作，只有一格被下一次同格记录盖掉。基线不会在某一瞬间整体作废，也不会因为一次重置让全组的分数同时归零。

格子按墙上的钟切，不按运行时长切，所以第 40 格永远是 20:00 到 20:30。这样每格记的是**节点在这个时段最快能有多快**，而不是随便 24 小时里的最低值。

格子多少决定了记录的时间粒度，也决定每格能放几次探测：格子少，每格盖的时间长，一个时段里的起伏都压成一个最小值；格子多，每格里的探测就少，记录可能只由一两次决定。48 能整除一天，每格也装得下好几轮检查，所以选了它。它跟 `sampling`、`interval` 是一类的，改了要一起考虑探测频率，不适合单独给用户配。

**代价。** 地板是“每格里最小值”再取最小，仍然是个最小值，偏向记最乐观的那一次。这跟它的用途是一致的（要的就是空载水平），但也意味着偶尔一次走运的探测会把地板压得略低，让每个节点的 `PRES` 都偏大一点。这个偏差是**大家一样**的，不改变名次，只影响 `tolerance` 相对的严格程度。

**更新。** 每轮先更新格子，再算分数，所以这一轮的观测立刻生效，反过来先算分再更新，节点变快就要等到下一轮才反映出来，没有好处。

**过期。** 没有单独的过期步骤：24 小时后，同一格会被下一轮记录覆盖，旧记录随之失效。所以基线永远来自**真正测过的时段**，不会像“到期就重置成当前值”那样，把眼下的拥堵误当成最快水平。某个时段一直拥堵，那个时段的记录会慢慢变高，别的时段照旧；只有长期都堵，整体基线才会升高，等于承认“这节点平时就是这样”。

**跳变。** 节点平稳或缓慢变化时，基线每次只移动一格带来的变化量，因为 30 分钟只换一格。以每天慢 144ms 的节点为例：一次性过期是 144ms 的突变；用格子之后，这个变化摊到一天的 48 次更新里，每次约 11ms。**不过，突发变化（换线路、换机器）还是会跳一下**：最后一格旧数据被覆盖时，最小值只能落到下一个最小值，跳的幅度就是变化本身。这是忘掉旧数据要付的代价，不是平滑能消掉的噪声。

**启动。** 第一轮写入的就是这一轮最快值，所以 `FLOOR` 一开始就是 `MIN`，不需要单独的降级处理。之后地板从一格开始慢慢填满，铺满一天要 24 小时。开了缓存时，重启会把整天的格子和长期失败率接着用；缓存不可用（没开、检查的目标或链路变了、记录过期了）就跟冷启动一样，从零开始攒。这期间每格盖的时段少，地板容易偏高——这是忘掉旧数据的代价，排序仍然成立。

### 缓存为什么只存地板和失败率

窗口之外的跨轮次状态只有两样：基线和长期失败率。`FAILR_NEAR` 从窗口里每条检查的时间算出来，不需要额外存；所以缓存里仍然只有 `FAILR_LONG` 一个失败状态，`FAILR_NEAR` 和 `MED`、`JIT` 一样属于可重建的窗口统计。重启后窗口清空，`FAILR_NEAR` 从零开始；`FAILR_LONG` 从缓存恢复，分数仍会压着刚失败的节点。如果要求门槛也跨重启精确，才需要把 `FAIL_NEAR` 和时间戳一起存——那是两个数，不是把两个视界合并。窗口只有 `sampling` 次检查（`sampling × interval`），而这两样一个要看 24 小时，一个要看 `τ = 45` 分钟。重启的代价因此极不对称：窗口几分钟就重建好了，`FLOOR` 要等下一个日低谷，`FAILR_LONG` 要等节点**再失败一次**才有证据。

窗口里的样本不存——二十来分钟就能重建，而要留住那几百次检查，空间要多两个数量级。

**记录按“路径 + 节点”算，不按检查算。** 记的是“这个节点经这条路走”的样子：目标或链路不同就各记各的；目标与链路相同、只有窗口或间隔不同的两个检查，会共享它们共同那几个节点的记录。这样分享够精确——同一条路径上，一个窗口采样两次和一天采样一百次，最后每个节点的地板是同一个值，两边差的只是噪声，不是来源。写入的一方只动自己测过的节点，读回来的值描述的就是节点本身。

记录只在 24 小时内有用，也就是地板能活多久；过了这个时间的记录会被丢掉，所以一个再也不被检查的节点不会永远占着位置。

### 为什么阈值是两倍，权重是 0.5

`BAD` 的判据是“慢到自己最好水平的两倍”，权重 `0.5` 让一个“每次都翻倍”的节点在标尺上加 500。两个数都不是拟合出来的，各有各的道理。

**为什么是两倍。** 两倍就是“耗时翻了一番”，也是最常用来判断一条线路开始排队的门槛。定得太低（比如 1.5 倍），正常的抖动和探测波动也会越线，每个节点都带着一截 `BAD`，彼此就分不出来了——这一项本来要区分的是“偶尔排队”和“一直排队”。定得太高（比如 3 倍），只有持续的长队够得着，几乎所有节点都归零，这一项等于不存在，分数退回去只看深度。两倍落在中间：正常波动够不到，真排队一定越得过去。

**为什么是 0.5。** 它把“频率”换算到和“深度”同一把尺子上。`PRES` 的量级在 0 到 1 之间，而一个“每次都翻倍”的节点，应该被判得和最糟的常驻排队差不多差，也就是加一个接近 1 的量。取 0.5，意味着“每次翻倍”比“常驻排队 50%”稍重一点。这个量级是判断，不是拟合。

它也不是随手取的，但不需要精细调——它定的是**换算率**：几次坏检查等于一个百分点的排队。换算率一变，边上的节点就换人：宽一点，多收一两个只是略差的；窄一点，只留最干净的。所以这是个策略问题——你希望“偶尔卡一下”在多大程度上等价于“一直慢一点”。明显不同的节点之间，先后不取决于这个数，只有卡在带宽边缘的那几个会。

这两项**必须分开**，因为它们抓的是不同的毛病：

| 节点 | `PRES` | `BAD` | 只按深度排 | 只按频率排 |
| --- | --- | --- | --- | --- |
| 快但常掉线 | 很低 | 很高 | 第一 | 中游 |
| 慢但很稳 | 中等 | 很低 | 中游 | 第一 |
| 又慢又常掉线 | 很高 | 很高 | 垫底 | 垫底 |

只用其中一个，另一类明显的毛病就会被放过。

### 误差公式的分布假设与重抽

误差公式的系数来自正态近似，而实测的延时不是正态的：偏度常在 3–4、峰度十几，尾部又厚又长，所以这些公式只是近似——在这份数据上，它们把 `quick` 的误差高估约 15%、`idle` 约 28%，`JIT` 那一项约 70%。

想要不假设分布，可以用**重抽**（bootstrap）：把窗口里的检查有放回地重抽 128 次，每次重新算分数，取这些分数的标准差。它的有效性可以用已知分布和噪声生成的数据来验证——真实噪声已知，重抽估计与它的比值在正态、对数正态、指数、均匀、三角 `f(x)=x`、柯西、重尾混合等形状下，中位数都在 0.8–1.1 之间。代价是每节点每次排名重建约 20µs（35 个节点约 0.7ms）；当前实现没有采用，保留闭式近似。

## 调试

想在自己的线路和负载下核对这套估计，直接问 API（组名是中文要 URL 编码）：

```bash
curl -s 'http://127.0.0.1:9090/private/health/Name/windows?ahead=2&configs=1:5,1:10,2:5'
```

`rho` 比的是全体节点的名次，`agreement` 比的是 pool 的成员——负载均衡从整个 pool 里取连接，pool 一样就是一样，内部谁排第一不影响。窗口越长，`rho` 未必越高：它会把节点早先的状态混进对紧接着几次检查的预测里。`agreement` 奖励稳定，`reaction` 和 `recovery` 报的是这份稳定的代价。窗口要「`样本数 × stride` + `ahead`」次检查才测得出来，而组默认只留 `sampling` 次。要让采样数和保留次数就地调整、不必重启，已收集的检查也不会丢：

```bash
curl -X PUT 'http://127.0.0.1:9090/private/health/Name/history?sampling=15&extra=60'
```

`sampling` 是算法采纳的次数，省略则保持当前值；`extra` 是采样数之外多留的次数，只用于诊断，省略或给 `0` 就只留采样数。

参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `ahead` | `8` | 窗口要预测其后多少次检查 |
| `configs` | 默认网格 | `stride:samples` 列表，如 `1:15,2:10`。`stride` 是隔几个检查取一个，`samples` 是窗口里的样本数 |

字段

| 字段 | 说明 |
| --- | --- |
| `interval` | 检查记录的实际间距（中位数），不是配置里写的值 |
| `nodes` | 参与测量的节点数 |
| `checks` | 最长的那份历史有多少次检查 |
| `ahead` | 每个窗口被要求预测其后多少次检查 |
| `stride` | 隔几个检查取一个，`1` 为连续 |
| `samples` | 窗口里的样本数，窗口跨度为 `interval × stride × samples` |
| `span` | 窗口的实际宽度 |
| `windows` | 该窗口在历史上被摆放的位置数，其余字段是这些位置的平均 |
| `rho` | 窗口排出的顺序与其后检查排出的顺序的秩相关：`1` 完全一致，`0` 等于瞎猜。饱和后没有分辨力，只作历史太短时的参考 |
| `delta` | `rho` 的标准误差；`windows` 少时会塌成 `0`，那是没有精度可言 |
| `pool` | 该窗口下 band 平均放进来几个节点 |
| `agreement` | 窗口选出的 pool 与其后检查选出的 pool 的 Jaccard 相似度：`1` 是同一批节点，`0` 是没有一个相同 |
| `exact` | 两个 pool 完全相同的位置占比；`agreement` 把部分重合也算作相似，`exact` 只认完全一样 |
| `reaction` | 节点变慢之后，窗口要几次检查才把它移出 pool；`ahead + 1` 表示到视界尽头仍在 pool 里，没有 `reactions` 时不出现 |
| `reactions` | 历史上“正在被使用、随后变慢”的次数；失败不算，因为失败在当次检查就被剔除 |
| `recovery` | 反方向的同一件事：节点恢复之后，又要几次检查才重新进入 pool。视界取窗口宽度（`samples × stride`），给近因权重衰减留出足够空间；通常比旧窗口快，因为不用等失败满 `sampling` 次才离开；视界内没回来记为“视界 + 1”，没有 `recoveries` 时不出现 |
| `recoveries` | 历史上“正在被使用、被剔除后又恢复”的次数 |
| `note` | 一个窗口都测不出来时，说明还差多少 |
