# 节点评分

一个组如何把[健康检查](/zh/configuration/shared/health-check/)的结果变成它挑选节点的依据，以及每一部分为什么是这个形状。

本页讲的是理由，不是字段：可配置项见[负载均衡](/zh/configuration/outbound/loadbalance/)和
[URL 测试](/zh/configuration/outbound/urltest/)。

### 两个问题

一个节点可以以两种彼此独立的方式评判，而一个组只需要回答其中一个：

- `quick` 回答：**离我多远？** 170ms 的节点比 40ms 的节点拖慢它承载的一切。
- `steady` 回答：**有多稳？** 一个平时 200ms、偶尔卡三秒的节点，会让恰好落在那次卡顿上的流量变慢。

### 统计量

每个统计量都只用**成功**的检查计算。失败的检查等满了超时，它的延时说明不了节点在正常时的延时：
失败的比例被单独携带，在生成分数的地方混入。

记 `x₁ … xₙ` 为成功检查的延时，`n` 为其数量：

```
MED     = median(x₁ … xₙ)
JIT     = 1.4826 × median(|xᵢ − MED|)
DEV     = (1/n) × Σ|xᵢ − MED|
```

`MED` 表达节点远近，`JIT` 与 `DEV` 度量的是同一件事的两种汇总方式：每次检查偏离该节点自身中位数多少。
两者都以节点自己的中位数为基准，都不含距离信息：稳定在 4s 的节点和稳定在 100ms 的节点，抖动是一样的。

- **`MED`** 取中位数而不是平均值。平均值会被单次慢速检查拉走，于是它描述的是窗口里最差的那一刻，而不是节点。
- **`JIT`** 是这些偏差的**典型**值，即中位数。单次慢速检查拉不动它：它必须先越过样本的中间位置。
  `1.4826` 把偏差的中位数换算成标准差的估计，使 `JIT` 与 `DEV`、以及下面的标准误差处于同一尺度
  （正态样本下 `MAD ≈ 0.6745σ`，见下文“为什么不用标准差”）。
- **`DEV`** 是这些偏差的**平均**值。每次检查按自己的份额计入，因此偶发的尖峰不会被忽略，重复出现则累加。

两者回答的是同一批偏差的不同问题，这正是两个目标的全部区别：

| | 问题 | 结论 |
| --- | --- | --- |
| `JIT` | 它通常波动多少？ | 卡过一次的节点仍然是近的节点 |
| `DEV` | 它总共多付了多少？ | 会卡的节点不是稳的节点 |

### 分数

```
cost    = MED + JIT    # quick，节点通常的代价，毫秒
cost    = DEV          # steady，它偏离自身典型值多少，毫秒
failure = min(TIMEOUT, 3 × cost)
score   = (ALL - FAIL) / ALL × cost + FAIL / ALL × failure
```

两个分数都以毫秒计，但含义不同，它们对应开头的两个问题：

- `quick` 是**节点通常的代价**。一个近但不稳的节点和一个更远的节点代价一样，所以 `JIT` 按自身尺度加一次。
- `steady` 只取 `DEV`，不含 `MED`：不问它有多快，只问它有多稳。
- 失败按自身占比混入。一次失败相当于三次成功：它毕竟需要重试，失败按节点自身的尺度计分。
  若按超时计分，一个很快但失败过一次的节点会被埋在所有从未失败的节点之后，无论延时如何；
  以超时为上限，则保证分数不会超过它，因为一次尝试最多也就是等满超时。

### 容差

组不会为它无法信任的差异切换。区间是最优节点周围“视为同样好”的范围。
默认值不同，因为两个目标衡量的**量**不同：

| 目标     | 分数        | 默认   |
| -------- | ----------- | ------ |
| `quick`  | `MED + JIT` | `50ms` |
| `steady` | `DEV`       | `10ms` |

区间还要加上一份**分辨力余量**，即噪声：

```
band = tolerance + 2√2 × JIT_best / √n
cut  = score_best + band
```

`tolerance` 描述的是**真实差距**，而比较只能看到**观测值**。
采样越多，噪声越小、`band`越接近配置值，但**永远不会窄于它**。

!!! note 为什么是相加而不是取较大者

    若取 `max`，在 `tolerance`（例如 50ms）大于余量（例如 7ms）时，余量等于不存在，
    切点上的节点会按测量噪声每轮进出。

噪声尺度取 `JIT_best`，这个选择说明两件事：

- **不取 `DEV_best`**：`DEV` 是**它总共付了多少**，`steady` 用它排序，所以一次尖峰必须全额计入
  “会卡的节点不是稳的节点”；余量要的是“这个读数能偏多少”，用中位数的 `JIT` 才不会被一次慢探测推走。
- **也不取分数的完整标准误差 `SE`**：`SE` 才是精确的分辨力，但它是平方和，一次慢探测照样会把它撑开，
  而区间决定“谁算同样好”，撑开就等于让明显更差的节点也算进来（见[噪声](#噪声)）。
  代价是这条余量是一条**下界**：实测分数的标准误差约为它的 2.8 倍，所以 `band` 保证的是“不比容差窄”，
  不是 95% 的分辨力——`tolerance` 应当按这个前提来配。

### 连接保留

开启打断链接配置后，在用节点被替换时，它已有的连接不一定被中断。刚离开选择的节点，只要超出区间的部分仍在两个估计的噪声之内，就会被保留，
以免因为一次不具代表性的测量而断开连接：

```
noise     = 2 × √(SE_node² + SE_best²)
allowance = band + min(band, noise)
```

噪声以区间本身为上限，因此节点最多存活到距最优节点**两倍带宽**处——迟滞是用来扛噪声的，不是用来留住明显更差的节点。

噪声这一项怎么合成、为什么乘 2、以及它和选择容差里的余量差在哪，见[噪声](#噪声)。

两个目标的容许量在实践中的差别，来自它们的噪声大小：

- `quick` 默认 50ms，而 `SE` 在 `sampling` 10 时通常是十几毫秒（`sd(x)`、`sd(偏差)` 各占一项），
  噪声在带宽面前还不算大，所以容许量基本上是“带宽 + 两个标准误差”，偶尔封顶。
- `steady` 默认 10ms，而 `SE = sd(|xᵢ − MED|)/√n` 在 `sampling` 10 时可以到几十毫秒，
  封顶经常生效，容许量于是退化为 `2 × band`。这里用样本的离散度、而不是 `JIT`：保留问的是
  “值不值得断”，对“可能只是一次瞬时尖峰”更宽容是对的——一次慢探测让 `sd` 变大，于是连接被保留得更久，
  这正是要的结果；而区间用的是稳健的 `JIT`，两者不同源，是有意的。

`urltest` 组没有第二层：它一次只用一整个节点，所以迟滞做在**选择**里——在用的节点只要分数不超过最优节点的
`Limit(best)` 就保住位置，也就是**一个**带宽而不是两个；它同样以最优节点为基准，理由相同。

这是为连接做的迟滞，与选择是两个问题：选择问的是“新连接该用哪个节点”，保留问的是“值不值得断掉某个节点已有的连接”。

### 噪声

这里的每个统计量都是小窗口上的估计，所以分数是估计，分数之间的比较也是估计。噪声有两个层次：一个分数的，
两个分数之差的。选择与保留用的是同一个模型，只是代入的节点不同。

**一个分数的噪声**。分数是 `n` 个样本算出来的，它“再测一遍会浮动多少”就是标准误差，等于所用统计量自身的离散度除以 `√n`：

```
SE = sd(统计量) / √n
```

`√n` 是“平均 `n` 次之后还剩多少”：样本越多，分数越接近真值。两个目标的分数由不同的统计量构成，所以 `sd(统计量)` 也不同。

`steady` 的分数就是 `DEV`，即一批偏差的均值，它的离散度是**偏差自身的**：

```
SE(DEV) = sd(|xᵢ − MED|) / √n
```

`quick` 的分数是两项之和，两项各有误差，再按方差合成。中位数在 `n` 个样本上的标准误差是 `1.2533σ/√n`
（渐近结果：中位数的方差是 `1/(4n·f(m)²)`，正态下即 `(1.2533σ)²/n`——它只用到样本的排序，比均值差四分之一）。
抖动是**偏差的中位数**再乘 `1.4826`，所以它的标准误差是 `1.4826 × 1.2533` 倍于单个偏差的标准误差：

```
SE(MED) = 1.2533 · sd(x) / √n
SE(JIT) = 1.858 · sd(|xᵢ − MED|) / √n
SE      = √( SE(MED)² + SE(JIT)² )
```

**两个分数之差的噪声**。`SE_node` 与 `SE_best` 是各自“再测一遍会浮动多少”，它们本身是算出来的定值，不会浮动；
浮动的是分数，所以 `score_node − score_best` 也会浮动。两个节点被分别测量，误差互相独立，因此**方差可以相加**：

```
SD(score_node − score_best) = √(SE_node² + SE_best²)
```

先平方相加、再开方回到毫秒，而不是把两个 `SE` 直接相加或相减：独立误差会互相抵消掉一部分，抵消多少正好由这个式子给出。

**为什么再乘 2**。正态分布下 `1.96σ` 覆盖 95% 的概率，工程上取整成 2，也就是“超出这个量，就不像是噪声了”。

**同一个模型在选择与保留里的两种代入方式**：

| | 和谁比 | 余量 | 为什么这样代入 |
| --- | --- | --- | --- |
| 选择：区间 | 最优 vs 一个**未知候选** | `2√2 × JIT_best/√n` | 切点对全体候选生效，只能假定候选与最优测得一样准；若改用各节点自己的 `SE`，越吵的节点余量越大，方向反了。这里刻意用稳健的 `JIT` 而不是 `SE`，见下 |
| 保留：容许量 | 最优 vs **这一个具体节点** | `2 × √(SE_node² + SE_best²)` | 对象是已知的，就用它自己的真实 `SE`；再以区间本身封顶，避免噪声大的节点赖着不走 |

两处的 `SE` 里都已经含了 `1/√n`，没有额外的除：样本越多，两边都自动收缩。选择这边写成 `2√2 × JIT_best/√n`，
是“两个同级估计”代入后的结果，`2√2` 把乘 2 和 `√2` 并成了一个常数。

**选择为什么不直接用 `SE`**。区间决定“谁算同样好”，如果余量跟着分数的全部误差走，一次慢探测就会把带宽撑开，
让明显更差的节点也算进来——方向与"一次探测不该决定选择"正好相反（见[容差](#容差)）。代价是余量比 `SE` 窄：
实测 `SE(score) ÷ (JIT_best/√n)` 的中位数是 **2.8** 倍，所以这个余量是一条**下界**，不是 95% 的分辨力。
保留没有这个问题——它只作用在已经选出来的节点上，宽一点只是少断几条连接，所以那里用真实 `SE`。

**相对噪声是 `1/√n`，与节点无关，只取决于样本数**——只是它相对的是节点自身的尺度，而不是 `DEV`。

带宽是一个配置值，不随样本数缩水，只会被余量加宽——所以不存在“采样不足就退化成追噪声”的阶段。
但窗口越长，读到的越是过去：**降低噪声与跟上变化是同一个旋钮的两端。**

!!! note ""

    需要澄清一个常见的直觉：**噪声不能被“剔除”**。按节点自身的尺度计，相对噪声对每个节点都是 `1/√n`，
    从每个节点的分数里减掉它，等于全体乘以同一个系数——排名与选择完全不变。
    噪声不是偏置（可以减掉），而是围绕真值的波动（减不掉）。能被减掉的只有它在**带宽**里的体现，
    也就是上面的分辨率项。

### 为什么不用标准差

样本标准差是度量离散度的常用做法，但在这里不合适，三个原因叠加：

1. **它以平均值为中心，而平均值会被离群值拉走。** 十次检查里一次慢速，均值从 449ms 抬到 897ms，
   剩下九次的偏差就被拿去和一个与它们无关的中心比较：它们 457ms 的偏差变成了 751ms，而它们一个都没变。
2. **它有平方，于是一个样本可以主导结果。** 在某个窗口里一次检查用了 3.15s，83% 的方差来自那一次，
   报告出来的离散度描述的是那一次探测，而不是节点。
3. **开方并不能把尺度还原。** `n` 个样本中一个 `X` 的尖峰，对平均偏差的贡献是 `X/n`，
   这正是它拖慢的连接份额；但对标准差的贡献是 `X/√n`——`n = 10` 时就已经高估 3.2 倍，窗口越长越离谱。

`DEV` 是同一个想法去掉这两个缺陷：线性，且以一个尖峰无法移动的中心为基准。在 200ms 与 800ms 之间来回的节点仍然读出 445ms，
所以不是说 `DEV` 忽略了不稳定——而是这个估计始终在描述节点。

### 为什么不用趋势

窗口是有顺序的，而上面所有统计量都没有用到它：把样本打乱，`MED`、`JIT`、`DEV` 都不变。
因此一个已经持续变差十分钟的节点，只要离散度相同，读数和一个稳定的节点一样。

半窗对比（`median(后半) − median(前半)`）确实能恢复这一信息，而且代价很低。它没有进入分数，是因为含趋势的分数会让
`interval` 变化时排名也变化，而排名必须是节点自身的性质，不是它被采样的节奏的性质。趋势属于决策，与容差并列，不属于测量。

它也需要小心：`sampling` 为 10 时，后半窗五个样本里连续两次异常并不能推动它的中位数，因此趋势要到第三次才会出现。
这使它成为一个比“最近一次检查”更慢的信号，而后者本来就在统计量里。
